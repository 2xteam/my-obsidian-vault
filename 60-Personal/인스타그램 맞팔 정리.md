# 인스타그램 맞팔 정리

내가 팔로우하는데 상대는 나를 팔로우하지 않는 계정을 추려서 팔로우를 취소한다.
계정은 `zang.f1t`. 데이터 추출은 로컬 스크립트로, 취소는 브라우저 UI 클릭으로 한다.

## 언제 쓰나

- 팔로잉 수가 팔로워 수보다 눈에 띄게 많아졌을 때
- 러닝 계정처럼 맞팔 목적으로 늘린 팔로잉을 주기적으로 솎아낼 때

## 1단계 — 데이터 받기

인스타그램 앱 → 설정 → 계정 센터 → **내 정보 및 권한 → 내 정보 다운로드** → JSON 형식.
메일로 오는 zip 을 풀면 이 두 파일이 필요하다.

```
connections/followers_and_following/followers_1.json
connections/followers_and_following/following.json
```

**두 파일은 구조가 다르다.** 여기서 한 번 헤맨다.

| 파일 | 최상위 | 아이디가 있는 곳 |
|---|---|---|
| `followers_1.json` | 배열 | `[].string_list_data[0].value` |
| `following.json` | `{ relationships_following: [...] }` | `[].title` |

## 2단계 — 차집합 뽑기

```python
import json, datetime
f = json.load(open('followers_1.json', encoding='utf-8'))
g = json.load(open('following.json', encoding='utf-8'))

followers = {e['string_list_data'][0]['value'] for e in f if e.get('string_list_data')}
rows = []
for e in g['relationships_following']:
    name = e.get('title') or e['string_list_data'][0].get('value')
    ts = e['string_list_data'][0]['timestamp']
    if name not in followers:
        rows.append((ts, name))

rows.sort(key=lambda r: -r[0])   # 팔로우한 시각 최신순
for ts, name in rows:
    print(name, datetime.datetime.fromtimestamp(ts).strftime('%Y-%m-%d %H:%M'))
```

`timestamp` 는 유닉스 초다. **최신순으로 보는 게 중요하다** — 최근에 팔로우한 계정은
상대가 아직 못 봤을 수 있으니 오래된 것부터 정리하는 판단에 쓴다.

## 3단계 — 브라우저에서 취소

프로필 → 팔로잉 모달을 열어 두고, **모달 안의 검색창으로 한 명씩 찾아서** 취소한다.
목록을 스크롤해 찾는 방식은 가상 스크롤 때문에 위치가 흔들려서 쓰지 않는다.

한 계정당 순서는 항상 이렇다.

1. 검색창을 `triple_click` 으로 전체 선택하고 아이디를 타이핑 (이전 검색어가 남으면 엉뚱한 계정이 나온다)
2. 3초 대기 — 서버 검색이라 즉시 뜨지 않는다
3. 첫 행의 `팔로잉` 버튼 클릭 → 확인창이 뜬다
4. **확인창 문구로 대상을 검증** (아래 참고)
5. `팔로우 취소` 클릭
6. 5~7초 대기

좌표는 창 크기 557×1030 기준으로 고정이었다.

| 요소 | 좌표 |
|---|---|
| 모달 검색창 | (260, 342) |
| 첫 행 `팔로잉` 버튼 | (445, 396) |
| 확인창 `팔로우 취소` | (270, 497) |
| 확인창 `취소` | (270, 545) |

## 함정

### 스크린샷으로 검증하면 안 된다

**증상** — 취소 직후 찍은 스크린샷에 두세 건 전의 화면이 나온다.
**원인** — 브라우저 페인 스크린샷이 DOM 보다 한 박자 늦게 잡힌다.
**해결** — 확인창 문구를 접근성 트리에서 텍스트로 읽어 검증한다.
`취소하시겠어요` 로 찾으면 `@아이디님의 팔로우를 취소하시겠어요?` 가 그대로 나오므로
**대상 아이디를 확정한 뒤에 취소 버튼을 누를 수 있다.** 83건 전부 이 방법으로 대조했다.

- 결과 1건 = 확인창 떠 있음 → 취소 진행
- 결과 0건 = 검색 결과 없음 → 이미 취소된 계정, 건너뜀

### "검색 결과가 없습니다" 는 오류가 아니다

이미 직접 취소한 계정이다. 114개 중 31개가 여기 해당했다.
검색 기능 자체가 죽은 것과 헷갈리니, **아직 팔로우 중인 아이디 하나로 먼저 검색해 보고**
결과가 나오는지 확인한 다음 본작업에 들어간다.

### 영역 확대(zoom) 는 지원되지 않는다

확인창 문구만 잘라 찍으려 해도 전체 스크린샷이 돌아온다. 토큰만 낭비하니 쓰지 않는다.

### 배치는 25 액션이 상한

한 계정이 8 액션(선택·입력·대기·클릭·대기·검증·클릭·대기)이므로 **배치당 3계정**이 최대다.

### 백업 시점과 현재 상태가 다르다

내려받은 JSON 은 과거 스냅샷이다. 그 사이 맞팔이 된 계정이 있으면 같이 취소된다.
**작업 직전에 다시 내려받는 것이 가장 안전하다.**

## 검증

작업 전후 프로필의 `팔로우` 숫자로 교차 확인한다.

```
작업 전 454 − 작업 후 371 = 83  ←  실제 취소 건수와 일치
```

숫자가 맞지 않으면 어딘가에서 클릭이 빗나간 것이다.

## 속도 제한

인스타그램은 짧은 시간에 팔로우 취소가 몰리면 일시 차단을 건다.
한 건당 10초 안팎(대기 3초 + 5~7초)을 유지하면 **시간당 350건 수준**이고,
2026-09-16 에 83건을 연속으로 처리했을 때 경고는 뜨지 않았다.
100건을 넘길 작업이면 중간에 한 번 끊고 가는 편이 낫다.
