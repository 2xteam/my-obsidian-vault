# CalmTouch

손끝이 닿는 곳마다 색이 번지고, 손을 떼면 천천히 잔잔해지는 **마음 진정 앱**.
장면(scene)을 골라 들어가면 전체 화면에서 마우스 · 손가락 · 휠 · 기울기로 만진다.

> **2026-09-10: 이름 확정 · 골격 · 장면 19개 · 저장소 첫 푸시.** Vercel 프로젝트 `calmtouch` 는 사용자가 만들었다.
> DNS 와 환경 변수(`NEXT_PUBLIC_COOKIE_DOMAIN`, Config 타입)는 확인 필요. 아래 "예정 작업" 참고.

## 이름 (2026-09-10 결정)

**CalmTouch** — 진정(Calm) + 만지기(Touch). Snap 계열처럼 **동작을 이름에** 넣었다.
후보는 CalmLog · MindLog · RestLog 였는데, "기록" 뉘앙스 없이 만져서 진정한다는
것만 말하는 이름을 사용자가 골랐다.

카테고리 라벨은 **마음 쉼** (CALM) 이다. 처음엔 다른 카테고리처럼 "마음 기록" 으로 두었는데,
이 앱은 아무것도 기록하지 않아서 랜딩에 올리며(2026-09-10) "마음 쉼" 으로 확정했다
→ [[서비스 카테고리와 카피 원칙]]

## 레퍼런스

toukoum.fr 첫 화면의 물감 번짐. 소스는 `github.com/toukoum/portfolio` 의
`src/hooks/use-FluidCursor.tsx` 이고, 그 안은 Pavel Dobryakov 의
**WebGL-Fluid-Simulation (MIT)** 을 거의 그대로 가져온 것이다.

레퍼런스가 쓰는 값 — 색은 오래 남고 흐름은 금방 멎는 "물감" 느낌의 원인이다.

```
SIM 128 · DYE 1440 · DENSITY_DISSIPATION 0.5 · VELOCITY_DISSIPATION 3
PRESSURE 0.1 · CURL 3 · SPLAT_RADIUS 0.2 · SPLAT_FORCE 6000
색: HSV(무작위 h, 1, 1) × 0.15 — 포인터 색을 0.1초마다 다시 뽑는다
```

우리 엔진(`lib/fluid/`)은 같은 알고리즘(Stable Fluids)을 **다시 썼다.** 셰이더
(`shaders.ts`)와 시뮬레이터(`FluidSim.ts`)를 나눴고, 장면마다 다른 매개변수를 넣는다.

### 입력 네 가지 — 모두 같은 `splat` 으로 들어간다

| 입력 | 어떻게 |
|---|---|
| 포인터 | 마우스는 **누르지 않아도** 번진다(레퍼런스와 같다). 손가락은 문지르는 동안, 멀티터치 |

| 흐름 | 2.2초 이상 가만히 두면 1.7초마다 한 방울. 끌 수 있다. 화면이 죽어 보이지 않게 하는 장치 |

## 결정 사항

- **플레이어의 짙은 바탕은 테마가 아니라 콘텐츠다.** 물감은 어두운 바탕 위에 가산돼야
  보인다. 목록 화면은 라이트 전용 원칙 그대로다 → [[앱 공통 UI와 아이콘]]
- 염료 밝기는 **0.15** 로 정규화한다(`lib/fluid/color.ts`). 어떤 색을 골라도 같은 세기로
  번진다. 1.0 이면 첫 터치부터 화면이 하얗게 탄다
- `devicePixelRatio` 상한 **2**. 유체는 해상도를 조금 낮춰도 티가 안 나고 고사양 폰의
  발열이 준다
- 목록 카드의 미리보기는 **실제 플레이 화면 캡처**(`public/thumbs/<slug>.webp` · `npm run thumbs`)다.
  처음엔 그라디언트였는데 실제 장면과 달라 보였다(2026-09-10 사용자 지적). 카드마다 WebGL 을 띄우지는
  않는다 — 이미지가 없으면 CSS 가 뒤의 그라디언트를 보여 준다. 캡처는 klead 의 playwright + swiftshader
- 도구 바의 흐름·소리·기울기는 **손잡이 있는 켬/끔 스위치**(2026-09-11 사용자 요청). 꺼지면 흐리게(opacity .55), 켜지면
  먹청 빛(`--accent-on-dark`)으로 진하게. "켬/끔" 글자는 없다 — 스위치 자리가 그 말을 대신한다. 지우기·전체 화면은 그대로 버튼
- UI 는 **탭하면 나타나고 3초 뒤 사라진다.** 문지르는 동안에는 늘리지 않는다 — 손을
  움직이는 내내 버튼이 떠 있으면 만지는 느낌이 깨진다
- **염료 최대 밝기 `dyeClamp` 1.0** — splat 셰이더에서 가장 밝은 채널이 1.0 을 넘으면 색 전체를
  함께 줄인다. 채널마다 따로 잘리면 한 가지 색 장면에서 같은 자리를 계속 문지를 때 고른 색이
  하얗게 탔다(헤드리스 확인에서 실제로 났다). 속도 텍스처에는 끈다
- 선형 필터링이 없는 기기는 염료 해상도 512 · 음영 끔. WebGL 이 없으면 안내 화면
- 문장은 해요체. **"치료 · 명상 · 효과" 라고 하지 않는다.** "잠깐 쉬어요" 정도로

| **https 가 아니면** 브라우저가 센서 이벤트를 아예 보내지 않는다 (LAN 의 `http://192.168…` 포함) | 켤 때 프로토콜을 보고 "https 로 열었을 때만 돼요" 안내 |
| iOS 13+ 는 사용자 동작 안에서 `requestPermission()` — 거부되면 조용히 아무 일도 없다 | 결과가 `granted` 아니면 설정 경로를 안내 |
| 안드로이드 크롬 사이트 설정 "움직임 센서" 차단 · 일부 기기는 `deviceorientationabsolute` 로만 옴 | 두 이벤트 모두 받고, 켠 뒤 1.8초 안에 값이 없으면 안내 |
| **효과가 너무 약해 "안 된다"로 보였다** — 유체 장면의 기울기가 무작위 한 점 splat 이었다 | 기울기에 수직인 선 위 다섯 점에 넓은 힘 → 화면 전체가 그쪽으로 흐른다 |
| 플랫폼이 Permissions-Policy 를 얹을 수 있다 | `next.config.ts` headers 에 `accelerometer · gyroscope · magnetometer = (self)` 명시 |

실기기 확인은 아직이다. 사용자가 다시 시험하면 안내 문구가 어느 단계에서 멈추는지 알려 준다.

## 함정

- **렌더 중에 `document` 를 보면 React #418(하이드레이션 불일치).** 전체 화면 버튼을
  `typeof document !== "undefined" && document.documentElement.requestFullscreen` 로 렌더에서
  판정했더니 서버 HTML 에는 없고 클라이언트에는 있어 터졌다. 기기 능력 판정은 전부 `useEffect`
  안에서 state 로 (기울기 · 전체 화면 · WebGL 지원)
- 헤드리스 확인은 `C:\Dev\klead\node_modules\playwright` 를 빌려 쓰고, WebGL 은
  `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` 로 켠다. 프레임이 느려
  3초짜리 UI 자동 숨김이 캡처 전에 끝나니, UI 를 찍으려면 로드 직후에 찍는다

- **진자에 바람을 상수로 더하면 뒤집힌다.** 윈드차임 첫 판에서 손을 쓸어 만든 바람이 중력보다 커
  관이 위로 넘어갔다. 바람 힘을 줄이고 각도를 ±1.1rad 로 잘랐다
- **소프트바디의 목표 위치를 자기 무게중심 기준 + 상수로 두면 끝없이 흘러내린다.** 슬라임이
  화면 아래로 가라앉았다. 화면 고정점으로 약하게(0.12) 당기는 항으로 바꿨다
- 매 프레임 `document.createElement("canvas")` 는 GC 를 흔든다 — 비 오는 창의 마스크 합성 캔버스는
  layout 때 한 번만 만든다

- **첫 슬라임은 "튕기는 젤리" 였다** (사용자: "전혀 슬라임 같지 않아요"). 슬라임은 스프링이 아니라
  점성이다 — 탄성 약하게, 이웃 속도 평균(점성)과 감쇠 세게, 복원은 속도에 직접 거는 "느린 기어가기"로.
  늘어났다 돌아온 자리가 뭉치고 꼬이므로 **매 프레임 둘레를 호 길이로 재배치**한다
- **유체 위에 매 프레임 넣는 값은 "프레임당 상수"라야 한다.** FluidSim 의 감쇠가 프레임당 고정(dt 상한 1/60)
  이라, 주입을 실시간 dt 에 비례시키면 느린 기기에서 주입이 감쇠를 앞질러 화면이 채워진다.
  속도도 매 프레임 더하면 누적된다 — 힘 160 이면 평형 속도가 수천이 되어 색이 화면 밖까지 쓸려 나갔다(8 이 맞았다).
  `dyeFromHex` 는 이미 0.15 로 정규화돼 있어 그 위에 0.02 를 곱하면 거의 보이지 않는다(0.14 가 맞았다)

- **왁뿌 = 왁스 뿌시기 볼.** 슬라임 겉에 왁스를 굳혀 놓고 손으로 눌러 바삭 부수는 장난감(속은 말랑, 겉은 바삭).
  사용자 정정(2026-09-11): 속은 슬라임이 아니라 **점토**에 가깝고, 부순 왁스는 **문지르면 속살과 섞여 사라져야** 한다
  두 번째 정정(같은 날, 제품 사진 셋): **조각조각 나야** 하고 모양은 **도넛**. 방사형 금 + 동심원 고리로 나누면
  거미줄처럼 보인다 — 흔들어 놓은 삼각 격자를 쓰면 파편답다. 조각은 옆면(어두운 층)·바닥 그림자·윗면 광택 한 점이
  있어야 "들린" 것으로 읽힌다. 눌린 자국의 그림자를 왁스 위 그대로 두면 드러난 파스텔 속살이 잿빛이 된다(0.11)
- **눌리는 끝은 "바닥까지 뚫림"이다** (2026-09-11 사용자). 자국 `depth` 가 1이 된 뒤에도 누르고 있으면 `through` 가 자라
  구멍이 난다. 슬라임은 손을 떼면 1.6초에 흘러 메워지고(구멍 안은 배경 그라데이션 + 벽·입술), 왁뿌는 점토라 남는다.
  **방사 그라데이션은 안쪽 원을 첫 색으로 채운다** — 구멍 둘레의 흰 입술을 바닥 위에 그리면 바닥이 잿빛이 된다. 벽·입술 먼저, 바닥은 클립해서 나중에
- **슬라임 색 고르기 = 덩어리 추가** (2026-09-11 사용자). 몸 색을 바꾸는 대신 그 색의 작은 덩어리가 본체 옆(세로 화면은 위/아래)에
  생긴다. 끌어다 본체에 닿게 놓으면 속살 캔버스(`tint`, 512²)에 그 색이 번지고 restArea 가 늘어 둘레가 부푼다.
  누른 채 문지르면 손가락 방향으로 `drawImage` 자기 복사(알파 0.55)로 색이 끌려 섞인다. 몸은 tint 를 몸 모양으로 잘라
  offscreen 에 그리고 빛(source-atop)·가장자리 투명도(destination-in)를 얹는다. 점토·왁뿌 모드는 예전처럼 몸 색이 바뀐다
- **겹이 보이면 겹 수를 늘려 옅게.** 메니스커스 7겹(알파 .075+) 이 "여섯 겹으로 쌓인 게 보여요" — 22겹으로 나누고 알파를
  7/22 배. 접촉 그림자도 6겹 → 14겹(0.04). 총 어둠은 같고 단이 사라진다
- **왁뿌는 껍질이 없는 자리에서 더 갈라지지 않는다.** `waxAt(u,v)` (wax 캔버스 알파) 가 0.3 아래면 shatter 를 건너뛰고,
  조각 후보도 껍질 알파 0.25 아래면 버린다. 조각이 하나도 없으면 소리도 없다
- **장면 고유 조정 값은 `Scene.controls`** (2026-09-12). `stepper`(min·max·default) 와 `switch` 두 종류. PlayScreen 이 패널에
  그리고 `engine.setParam(key, value)` 로 넘긴다. 엔진은 처음 값을 `ctx0.scene.controls` 에서 읽는다. 흐름 스위치는
  `idleDrift` 장면에만 뜬다(키캡처럼 뜻 없는 장면엔 안 보인다)
- **끌기용 `pointer-events: none` 은 실제로 끌기 시작할 때만** (2026-09-13). pointerdown 에서 바로 카드를 죽였더니 PC 에서
  그냥 누른 클릭이 링크에 닿지 않아 카드가 열리지 않았다. 6px 넘게 움직인 순간에만 `data-drag` 를 붙인다
- **PC 에서 카드 줄을 옆으로 갈 방법이 없었다** (2026-09-12 사용자). 스크롤바를 숨겨 두었으니 마우스 기기(`hover: hover`
  `pointer: fine`)에는 양 끝 화살표를 띄우고, 잡아 끌기(mouse 포인터만)도 받는다 — 끌었으면 손 뗀 자리의 카드 클릭을
  capture 단계에서 막는다. 휠은 건드리지 않는다(세로 스크롤은 페이지 것 · Shift+휠은 브라우저가 옆으로). `components/SceneRow.tsx`
- **로그아웃이 안 풀리는 건 코드가 아니라 Vercel 환경 변수다** (2026-09-12). 여섯 앱의 session·sessionCookie·logout 라우트는
  같다. calmtouch 배포에 `NEXT_PUBLIC_COOKIE_DOMAIN=.myjane.co.kr` 이 없어 `POST /api/auth/logout` 의 Set-Cookie 에
  `Domain=.myjane.co.kr` 줄이 빠지고(typelog 는 있음), JS 의 deleteCookie 도 host-only 만 지운다. 포털이 심은 도메인 쿠키
  `snap_auth=1` 이 남아 로그인 상태로 보인다. 변수를 Config 타입으로 넣고 재배포하면 끝(빌드 시점 값이라 재배포 필수)
- **왁뿌 속살은 점토 → 말랑이** (2026-09-13 사용자). 손을 떼면 `rest` (처음 원)로 damp 1.6 으로 천천히 돌아가고 자국도 슬로우
  라이징으로 사라진다. 뚫린 구멍은 캔버스를 실제로 지운 것이라 남는다 — 문질러 메운다
- **푸딩 키캡의 소스는 따로 얹은 한 겹** (2026-09-13 사용자: 더 두텁게). 몸통(우유빛, 높이 CAP_H−0.24)과 소스(0.24, 몸통보다 9% 넓어 턱이 진다)를
  따로 그린다. **LED 는 몸통까지만** — 소스까지 물들이면 캡 전체가 유리처럼 보여 소스가 사라진다. 앞·오른쪽 아래턱에 흘러내린 방울 다섯
- **키캡 진동** — `navigator.vibrate` (안드로이드 크롬 등). iOS Safari 에는 **없다**. 그래서 `SceneControl.requires: "vibrate"` 를 두어
  지원 기기에서만 스위치가 뜬다. 축마다 다른 패턴(청축은 짧게 두 번, 무접점은 길게 한 번)
- **말랑이는 모양을 기억하지 않는다** (2026-09-13 2차 정정: "변형하면 변형된 채로 유지"). 제 모양으로 돌아가는 힘(memory)을 없애고,
  손을 떼면 점토처럼 물리를 멈춘다(`simSteps = (clay || squishy) && !touching ? 0 : sub`). 자국도 안 사라진다. 스프링·벤드도 낮춰야
  (16·38) 누르는 동안 윤곽이 저절로 매끈해지지 않는다. **되돌아오는 순간 흐물거리는 젤리로 보인다** — 폼은 되돌아오지 않는다.
  왁뿌 속살도 같다. 기울기는 물리가 멈춰 뜻이 없으므로 두 장면에서 껐다
- **말랑이 점도 3배** (2026-09-13 사용자). 감쇠 7 → 21, 슬로우 라이징 2.4 → 7.2초, 눌리는 속도 0.25 → 0.45초.
  왁뿌도 같은 값(제 모양 복귀 damp 1.6 → 0.55)
- **키캡 케이스는 투명 아크릴이고 벽이 캡을 감싼다** (2026-09-13 사용자 사진). 바닥판(z 0) 위로 벽이 RIM 0.3 솟고 캡은 0.24 에서
  시작해 아랫부분이 잠긴다. **뒤·왼쪽 껍데기는 캡보다 먼저, 앞·오른쪽은 캡보다 나중에** 그려야 "안에 들어앉은" 것으로 보인다
- **첫 소리가 버려지던 이유는 AudioContext** (2026-09-13 사용자: "조금 지나거나 설정창을 열었다 닫아야 적용됨").
  브라우저는 사용자 동작 전 오디오를 멈춰 두고 `resume()` 은 **비동기**라, 같은 손짓에서 바로 낸 소리가 사라진다.
  캔버스 `pointerdown` 에서 `warmAudio()` 로 무음 한 조각을 흘려 깨운다. 설정이 늦게 먹는 것처럼 보였을 뿐 상태는 맞았다
- **얼굴은 화면이 아니라 구면 위 모델 방향에 붙인다** (2026-09-13 사용자: "계속 앞면만 바라봅니다"). 눈·코·귀를 방향 벡터로 두고
  투영해 자리와 **보임 정도**(n·카메라, pitch=sin(고도))를 구한다. 뒤로 돌리면 사라져 뒤통수가 된다. 구 자체는 어느 각도에서도 원
- **키링은 흔들지 않는다** (2026-09-15 사용자: "흔들거림이 정신없고 중력에 어긋난다"). 물리를 두 번 시도했다 —
  화면 평면에서 끌리게 하면 돌릴 때마다 휘둘리고, 중력으로 늘어뜨리면 공중에 매달린 꼴이라 탁자 위 장면과 맞지 않는다.
  **책상에 둔 키링은 그냥 가만히 놓여 있다.** 줄을 모델 좌표(z=0 탁자면)에 곡선으로 한 번 깔고 케이스와 함께 돌기만 한다 —
  흔들림 0, 자리 안 튐, 어느 각도에서도 보인다. 그림자도 탁자에 함께 깐다. 매단 모서리는 앞오른쪽(처음 각도에서 화면 아래 빈자리)
- (폐기) 아래는 두 번의 실패 기록 — 다시 물리로 돌아가지 말 것 (2026-09-13 사용자: 자리가 튀고 겹친다). 카메라 부호로 모서리를 고르면 각도가 바뀔 때 **순간이동**한다.
  모델의 한 모서리에 매달고 구슬을 yaw 를 먹인 평면에서 베를레로 푼다 — 케이스가 돌면 매단 자리가 원을 그리며 줄이 끌린다.
  거리 구속만 두면 접혀 뭉치므로 **바깥으로 미는 힘 + 앞 두 알 방향으로 펴는 힘**이 필요하다. ry 부호로 앞뒤를 나눠 그려 케이스와 겹치지 않는다
- **키링 크기는 1.5배**, 소리·LED 는 **기본 켜짐**, 지우기는 도구 버튼 옆 되돌리기 아이콘으로 옮겼다 (2026-09-13 사용자)
- **키캡은 돌려 볼 수 있다** (2026-09-13 사용자). 빈 곳을 끌면 yaw(가로)·pitch(세로 눌림 0.12~0.95)가 바뀐다. 투영이 축측이라
  각도는 상수 둘일 뿐이지만, **화가 알고리즘의 앞뒤가 통째로 뒤집힌다** — 가까운 쪽을 `CT >= 0`·`ST >= 0` 부호로 구해
  먼 껍데기·모서리는 캡보다 먼저, 가까운 쪽은 나중에 그린다. 상자의 옆면 넷도 매번 깊이순으로 정렬하고, 밝기는 고정값 대신
  면의 화면 법선으로 구해(`faceLit`) 돌려도 빛이 왼쪽 위에 그대로 있다
- **돌리면 맞히기도 달라진다.** 윗면 + 아래로 늘인 사각형으로 대충 맞히던 것을 **여섯 면 전부**(윗면 + 옆면 넷)에 대한
  점-다각형 검사로 바꿨다 — 어느 각도에서도 실루엣과 정확히 같다. 가까운 키부터 보므로 가려진 키는 눌리지 않는다
- **숫자는 모델이 아니라 화면에 매단다.** 모델의 한 점에서 재던 것을 물체의 화면 윗끝(반지름×pitch)에서 재도록 바꿨다 —
  돌리면 숫자가 케이스와 겹쳤다
- **크기는 yaw 와 무관해야 한다.** 폭을 `cols·CT + rows·ST` 로 재면 돌릴 때마다 확대·축소가 출렁인다. 바깥 반지름으로 잡는다
- **케이스 선도 앞뒤를 나눠 그린다** (2026-09-13 사용자 지적). 윗테 네 변을 한 번에 그었더니 **뒤쪽 변이 키캡 위에 얹혀**
  캡을 가로지르는 흰 선이 됐다. 뒤·왼쪽 변은 캡보다 먼저, 앞·오른쪽 변만 캡보다 나중에. 오른쪽 윗테 면도 뒤쪽이라 먼저 그린다.
  화가 알고리즘에서는 **면뿐 아니라 선도** 깊이 순서를 지켜야 한다
- **아크릴은 면이 아니라 모서리로 보인다.** 앞쪽 벽을 알파 0.42 로 칠했더니 흰 막이 세 겹 겹쳐 안쪽 축 색이 죄다 씻겼다.
  면은 0.16~0.3 으로 거의 투명하게 두고 **모서리 선**을 또렷하게 그리는 쪽이 유리답고 속도 잘 보인다
- **스위치는 사진대로** — 우유빛 받침 + **십자 스템**(막대 둘을 겹친다) + 맑은 덮개(알파 0.28, 스템 색이 비친다). 받침을 축 색으로
  물들이고 높이를 0.14 로 잡아, 캡 아래로 드러나는 띠가 곧 "무슨 축인지" 를 말해 준다
- **키링은 길게** — 케이스 왼쪽에 박힌 고리 → 볼 체인 여덟 알 → 랍스터 클래스프. 화면 공간에서 그린다(금속은 각도와 무관).
  위로 뻗으면 숫자와 겹치니 옆으로 눕힌다
- **축하 소리는 칩튠** (2026-09-13 사용자). `gamePop`(동전 두 음)·`gameFanfare`(계단 아르페지오 + 반짝임). 사각파에 장3화음
  계단(0·4·7·12·16·19 반음)만 밟아, 어느 순간에 터져도 불협이 나지 않는다. 자릿수가 커지면 음이 많아지고 조금 높아진다.
  도구 바의 "소리" 가 켜져 있을 때만 난다
- **키캡 축하 크기는 끝의 0 개수로 정한다** (2026-09-13 사용자: 모든 단위에서 나게). 10·20·110 은 열 단위(동전 소리·링 1),
  100·200·1300 은 백 단위(팡파르·링 2), 1000·2000 은 천 단위로 더 크게. 자릿수가 늘어나는 순간(10·100·1000)만 글자도 커진다
- **카드 줄의 옆 자리도 기억한다** (2026-09-13). `SceneRow` 가 `sessionStorage["calmtouch:row:<path>:<label>"]` 에 scrollLeft 를 남기고
  마운트 때 되돌린다 — ScrollKeeper(세로)와 같은 방식. 스냅 자리라 바로 놓아도 어긋나지 않는다
- **키캡 횟수는 풍선 숫자** (2026-09-13 사용자). 글자마다 그림자·짙은 테·파스텔 세로 그라데이션·빛점, 살짝 따로 흔들림. 누르면 통통(bounce),
  자릿수가 늘면(10·100·1000) 글자 크기가 자릿수만큼 커지고(1 + 0.16×(자릿수−1), 최대 1.9배) 색이 돌며 링 n 개 + 종이 조각 14+10n 개 축하
- **패널 설정은 장면을 넘어 유지된다** (2026-09-13 사용자). `lib/prefs.ts` — 소리·기울기·흐름 켬/끔과 조정 값을 localStorage
  `calmtouch:pref:*` 에 남긴다. 조정 값은 **장면이 아니라 키**로 기억한다(`ctl:count`, `ctl:led`, `ctl:switch`) — 파스텔 키캡에서
  6개·무접점으로 두면 타자기 키캡도 그렇게 열린다. 읽을 때 장면 범위로 검증(스텝퍼 clamp · choice 는 선택지 안). 엔진은 만들 때
  `sound` 를 받고, 기본값과 다른 조정 값은 만든 직후 `setParam` 으로 넘긴다. 기울기는 https 일 때만 자동으로 켠다(iOS 는 값이 안 오면 안내)
- **도구 패널은 밖을 누르면 닫힌다** (2026-09-12 사용자: 닫기 버튼이 불편). `pointerdown` 을 capture 로 받아 패널·도구 버튼
  밖이면 닫는다 — 캔버스를 만지기 시작하는 손짓이 곧 닫기다. 열림 기억(localStorage)은 뺐다 — 저절로 닫히는 패널은 기억할 게 없다
- **조정 값 `choice`** — 여럿 중 하나(축). `options[].color` 가 있으면 칩 앞에 색 점. `setParam` 값은 number | boolean | string
- **플레이어 UI 는 저절로 숨지 않는다** (2026-09-11 사용자: "숨기고 싶을 때 숨기지도 못하는 불편한 존재"). 3초 자동 숨김을
  없앴다. 상단에 뒤로·도구 버튼 둘만 늘 보이고, 제목·흐름·소리·기울기·색·지우기·전체 화면은 도구 버튼 아래 떠 있는
  **패널**(`.play-panel`) 에 있다. 열림 상태는 `localStorage["calmtouch:panel"]` 에 남아 다음 장면에도 이어진다. Esc 로 닫힘.
  캡처 스크립트는 색 칩을 누르려면 패널을 먼저 연다
- **목록은 카테고리 줄 + 옆으로 밀기** (2026-09-11 사용자). `app/(app)/scenes/page.tsx` 시트 안 `.scene-row` 가
  `overflow-x: auto; scroll-snap-type: x mandatory`, 카드 폭 `min(72vw, 236px)`. 시트 안쪽 여백(`--row-pad`)을 음수 여백으로
  뚫어 가장자리까지 닿는다. 홈의 "가볍게 시작하기" 는 그대로 격자
- **왁뿌 구멍·색은 지키지 않는다.** 처음엔 안쪽 고리(48점)를 따로 두고 두께 제약으로 지켰는데 억지스러웠다. 속살을
  캔버스 한 장으로 두면 구멍은 빈자리, 색은 픽셀이라 손가락 방향으로 `drawImage` 자기 복사(알파 0.6)만 해도 끌려 섞인다.
  끌린 얇은 살은 같은 자리에 한 번 더 겹쳐(알파 0.5) 불투명하게 뭉친다
- **점토 도넛은 손 근처만 움직인다.** 손에서 R×0.42 밖의 점은 속도 0 으로 건너뛴다. 전체를 적분하면 압력 항이
  고리 전체를 부풀리고 구멍이 밀려 도넛이 콩팥이 된다
- **두께는 높이로 그리면 안 된다.** 몸을 아래로 밀어 겹친 "옆면" 은 원기둥처럼 인위적이었다. 점성 액체의 두께는
  가운데 농도·가장자리 투명도·가장자리 안쪽의 부드러운 어둠·바로 밑 접촉 그림자로 읽힌다. 그 어둠도 선 하나면
  접시 테두리가 되니 폭이 다른 옅은 선을 여러 겹 얹는다
  균열 선만 그리면 "갈라졌다" 가 안 읽힌다 — **조각이 실제로 떨어져 구멍이 뚫려야** 한다. 자국의 어두운 그림자가
  구멍 속 슬라임을 가리므로 왁스 모드에서는 그림자를 옅게(0.22) 둔다
- **장면에서 돌아오면 목록 자리를 지킨다** (2026-09-11). 플레이어의 뒤로 버튼은 `<Link href="/scenes">` 가 아니라
  `router.back()` (같은 출처에서 왔을 때 · 아니면 목록으로). 목록은 `components/ScrollKeeper.tsx` 가 경로별로
  `sessionStorage` 에 스크롤을 적어 두고 다시 들어오면 두 프레임 뒤 복원한다
- **점토는 물리를 "누르는 동안만" 돌린다.** 감쇠·스프링을 아무리 세게 해도 프레임마다 적분하면 흐느적거린다.
  손을 떼면 속도를 0 으로 두고 적분·재배치·스무딩을 모두 건너뛴다 — 매 프레임 스무딩은 모양을 서서히 깎아 먹는다
- **큰 도형의 `shadowBlur` 는 매 프레임 가우시안 블러다.** 헤드리스에서 스크린샷이 30초 넘게 걸렸고 폰에서도 무겁다.
  같은 모양을 조금씩 키워 옅게 여러 겹 겹치는 것으로 대신한다
- **`destination-out` 은 소스의 알파만큼 지운다.** 직전 `fillStyle` 이 반투명 그라디언트로 남아 있어 구멍이
  전혀 뚫리지 않았다 — 지우기 전에 불투명 색을 넣는다. 균열 선은 `source-atop` 으로 그려 왁스가 남은 곳에만 남긴다

```
바깥  r 58, stroke 4, opacity .55, dasharray "272 92.4", rotate(-62)
가운데 r 38, stroke 6, opacity .8,  dasharray "188 50.8", rotate(118)
안쪽  r 20, stroke 8,               dasharray "100 25.7", rotate(-8)
점    r 6.5 #e8d18a
```

16px 은 `app-icon-16.svg` — 굵은 고리 하나(r 50 · stroke 16)와 골드 점. PNG 파생은 `npm run icons`.

### 다음 장면 아이디어 — 구현 가능성 (2026-09-10 전부 구현됨 · 위 표)

전부 같은 플레이어(입력 네 가지 · UI) 위에 `engine` 만 바꿔 붙였다.

| 장면 | 어떻게 만드나 | 난이도 |
|---|---|---|
| 은하 | 파티클 수천 개가 나선 궤도로 돈다. 터치 반경 안은 밀어내고, 스프링으로 원래 궤도에 복귀 | 낮음 (Canvas 2D 로 충분) |
| 공 | 원 몇 개 + 벽 충돌 · 마찰. 터치로 튕기고 `deviceorientation` 이 중력 방향 | 낮음 |
| 모래 | 격자 셀에 모래 양을 두고 문지르면 이동. 셀 수가 많으면 WebGL, 적으면 Canvas | 중간 |
| 슬라임 | 스프링-질점 메시(예: 20×20). 누르면 눌리고 놓으면 되돌아온다 | 중간 |
| 구름 | 유체 엔진 재사용 — 밀도가 흰 안개, 배경은 하늘색 대신 짙은 색. 터치 반경으로 흩는다 | 낮음 (이미 있는 엔진) |
| 반짝이 | 파티클이 포인터에서 도망(반발력) + 배회. 가까이 오면 밝아진다 | 낮음 |

시작은 **구름(엔진 재사용) → 은하 · 반짝이(Canvas 2D 파티클) → 공 → 슬라임 → 모래** 순이 무난하다.
