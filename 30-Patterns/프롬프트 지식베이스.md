# 프롬프트 지식베이스

[[AIKit]] 이 다루는 프롬프트의 원본. **OpenAI API 를 부를 때 코드가 들고 갈 문장**과,
**사용자에게 돌려줄 이미지 생성 프롬프트**를 함께 둔다.

호출 규약(모델 분리 · `response_format` · 검토 화면 · 토큰 차감)은
[[OpenAI Vision 추출 패턴]] 을 그대로 따른다. **여기는 다른 점만 적는다.**

## ⚠️ 무엇이 검증됐고 무엇이 안 됐는지

이 노트가 자산이 되려면 이 구분이 먼저다.

| | 상태 |
|---|---|
| 딥링크 URL 형식 | **문서로 확인** (2026-09-17). 실기기 미검증 |
| 데이터셋 규모·스키마·라이선스 | **확인** — HF 페이지 |
| YouMind README 실제 129개 | **실측** — 직접 내려받아 파싱 |
| Lexica API 죽음 | **실측** — 500 응답 |
| `sargonelizabeth` 악성 리포 | **확인** — README 직접 읽음 |
| **아래 이미지 생성 프롬프트** | **미검증.** 이미지 모델에 한 번도 돌리지 않았다 |
| Gemini `?q=` 가 이미지 생성까지 가는지 | **미확인** |
| 모바일에서 딥링크가 앱으로 넘어가는지 | **미확인** |

아래 프롬프트들은 **설계 초안**이다. 실사용 결과가 나오면 이 노트를 고치고
`updated` 를 올린다.

---

## 두 종류를 절대 섞지 않는다

이 앱에는 성격이 정반대인 프롬프트가 둘 있다. 코드에서도 파일을 나눈다.

| | A 시스템 프롬프트 | B 이미지 생성 프롬프트 |
|---|---|---|
| 누가 받나 | **OpenAI API** | **사용자** (그리고 남의 AI) |
| 어디 사는가 | `lib/prompts/system/*.ts` — 서버 | `aikit` DB · 화면 · 클립보드 |
| 바꾸면 | 앱 동작이 바뀐다 | 결과물이 바뀐다 |
| 사용자가 보나 | **아니다** | 그렇다. 복사해서 가져간다 |
| 길이 | 길어도 된다 | **길면 딥링크가 막힌다** |

⚠️ **A 를 사용자에게 노출하지 않는다.** 응답에 시스템 프롬프트를 실어 보내지 않고,
에러 메시지에도 담지 않는다.

# A. 앱이 OpenAI 에 보내는 것

## ⚠️ 2026-09-18 기획 정정 — 역할을 잘랐다

**아래 A-1 의 원래 설계(장면·조명·색·구도 태그)는 폐기했다.** 그게 문제였다 —
기초 프롬프트가 이미 장면과 분위기를 정해 두는데 사진에서도 같은 것을 뽑아 오니
**둘이 경쟁해서 논점이 흐려졌다.** 결과가 이도 저도 아니게 된다.

| | 누가 정하나 |
|---|---|
| 장면 · 조명 · 색 · 카메라 · 구도 · **자세** | **기초 프롬프트** |
| 피사체의 생김새 — 얼굴 · 머리 · 장신구 · 옷 · 로고 · 신발 | **사진** (그대로 옮긴다) |

즉 **프롬프트의 내용이 우선**이고, 사진은 그 안에 들어갈 피사체를 준다.
사진 속 인물이 기초 프롬프트의 자세를 취한 모습이 결과다.

아래 A-1·A-2 는 **정정 전 기록**으로 남긴다. 실제로 도는 것은
`aikit/lib/prompts/system.ts` 다 — 거기가 원본이다.

### 정정 후 A-1 이 뽑는 것

```
subjects[]  kind · build · head(hair·eyewear·headwear) · accessories[]
            garments[](item·colour·material·pattern·graphic_or_logo·logo_placement·fit)
            footwear(type·colour·sole·laces·logo) · marks[]
            current_pose · cropped_or_hidden[]
text_in_image[]  content(그대로) · where · style
cautions[]
```

- **얼굴은 말로 옮길 수 없다.** 묘사해 재현시키면 반드시 닮은 남이 나온다.
  그래서 프롬프트가 "Image 1 을 그대로 쓰라"고 **지시하게** 만들고,
  말로 옮겨지는 것(머리·안경·옷·무늬·로고 자리·신발)만 빠짐없이 적는다
- **잘린 부분**은 `cropped_or_hidden` 에 적어 둔다. 보이는 것과 어울리게
  재구성하라고 프롬프트가 안내한다
- 문자는 **한 글자도 고치지 않는다.** 번역·반올림·교정 금지

⚠️ **`detail` 을 `low` → `high` 로 올렸다.** 거친 스키마에서는 low 와 high 의
결과가 **같아서**(2026-09-18 실측, 548 대 1,228 토큰) low 를 썼는데,
이제 **로고가 어디 붙었는지, 밑창이
무슨 색인지**까지 읽어야 해서 512px 로는 안 된다. 한 장에 755 → 1,435 토큰.

⚠️ **원경 사진은 피사체가 안 읽혀 전부 `null` 이 된다.** 그때 기초 프롬프트가
주제를 차지하지 않도록 막아 뒀지만, 사용자에게 "피사체를 못 찾았다"고 알리는
길은 아직 없다 — 남은 과제.

## A-1. 사진 분석 — 태그 뽑기 *(정정 전 기록)*

사진을 받아 **프롬프트 매칭에 쓸 태그**를 뽑는다. 수치 추출이 아니라 분류다.

- 모델: `OPENAI_VISION_MODEL`
- `response_format: { type: "json_object" }` · `temperature: 0`
- 이미지는 올리기 전에 축소 → [[이미지 업로드 패턴]]

### 시스템 프롬프트

```
You are a photo analyst for a prompt-recommendation service.
You look at one photograph and describe it as structured tags.
You never generate images and never write creative prose.

HARD RULES
1. Describe only what is visible. Do not infer, guess, or embellish.
2. Never attempt to identify anyone. No names, no age, no ethnicity,
   no nationality, no occupation, no emotional or personality inference.
   "one adult, face visible" is the level of detail allowed.
3. Never describe or transcribe anything that looks like a private
   document, ID card, address, or account number. Set a caution instead.
4. If a field is unclear, use null. Do not fill it to look complete.
5. Anything meaningful that has no field goes into "etc".
6. Output the JSON object only. No markdown fence, no commentary.
```

규칙 2가 이 앱에서 제일 중요하다. 얼굴 사진을 다루면서 신원·인종·나이를
추론시키면 **우리가 만들지 않아도 될 개인정보를 만들어 내게 된다.**

규칙 5(`etc`)는 [[OpenAI Vision 추출 패턴]] 과 같은 이유다 — 스키마를 처음부터
완벽하게 만들 수 없으니 버려질 것을 받아 두고, 반복해 쌓이면 정식 필드로 올린다.

### 출력 형태 — 그대로 예시로 보여 준다

```json
{
  "subject": {
    "people_count": 1,
    "framing": "full_body",
    "faces_visible": true,
    "pose": "low sprinter crouch, one knee up, fingertips on ground",
    "wearing": ["sleeveless top", "running shorts", "running shoes", "sports watch"]
  },
  "scene": {
    "place": "street",
    "time_of_day": "night",
    "indoor": false,
    "notable_objects": ["yellow tactile paving", "road", "trees"]
  },
  "light": { "source": "flash", "contrast": "high", "direction": "front" },
  "color": { "mood": "cool", "dominant": ["#0b0f10", "#d8b13a", "#8f8bbd"] },
  "composition": { "orientation": "portrait", "clutter": "clean", "negative_space": "top" },
  "activity": ["running"],
  "text_in_image": [],
  "suitable_for": ["poster", "portrait", "social_card"],
  "cautions": ["identifiable_face"],
  "etc": {}
}
```

**필드 값 후보**

| 필드 | 값 |
|---|---|
| `framing` | `full_body` `half` `close_up` `wide` `object_only` `none` |
| `place` | `street` `indoor` `nature` `gym` `stadium` `cafe` `studio` `other` |
| `time_of_day` | `day` `golden_hour` `night` `unknown` |
| `light.source` | `natural` `flash` `streetlight` `indoor` `mixed` `unknown` |
| `contrast` | `high` `medium` `low` |
| `mood` | `warm` `cool` `neutral` |
| `suitable_for` | `poster` `portrait` `social_card` `thumbnail` `product` `illustration` |
| `cautions` | `identifiable_face` `multiple_people` `possible_bystander` `possible_minor` `private_document` `low_quality` |

### `cautions` 는 화면까지 이어진다

이 필드는 분석용이 아니라 **제품 동작에 쓰인다.**

- `multiple_people` · `possible_bystander` → 공유 화면에서 제3자 동의 문장을 **강조**한다
  → [[H AIKit 구축]] Phase 5
- `possible_minor` → 공유 체크박스를 잠근다. 판단이 아니라 한 번 더 묻는 장치다
- `private_document` → 업로드 단계에서 경고
- `low_quality` → 프롬프트 추천 전에 다시 찍으라고 안내

⚠️ **`cautions` 를 법적 판단으로 쓰지 않는다.** 모델이 틀린다. 사용자에게 한 번 더
묻는 트리거일 뿐이고, 동의 책임은 여전히 사용자에게 있다.

## A-2 정정 후 — 기초 프롬프트에 피사체를 얹는다

고르는 일은 **사용자가 한다**(분위기 12칸 → 그 안의 프롬프트). 그래서 이 단계의
일은 "하나를 사진의 피사체에 맞춰 다시 쓰는 것" 으로 좁아졌다.

절 순서 — **피사체가 맨 앞이다.** 모델이 뒤쪽을 덜 따르고, 피사체가 요점이다.

```
ROLE · INPUTS · TASK
1. SUBJECT — IDENTITY LOCK   Image 1 을 그대로. 얼굴 새로 생성 금지
2. WARDROBE & DETAILS        옷·무늬·로고 자리·신발을 그대로
3. POSE & CAMERA             ← BASE
4. SCENE & LIGHT             ← BASE (분위기를 나르는 자리)
5. COLOUR                    ← BASE
6. TEXT                      사진에 문자가 있을 때만
7. OUTPUT                    비율을 **정확한 문자열로**
DO NOT
```

### ⚠️ 출력 계약을 앞에 두지 않으면 모델이 BASE 를 베낀다

처음 쓴 판은 `BASE: ... Keep all of it` 이었는데 모델이 그것을 **"BASE 를 그대로
출력하라"로 읽었다.** 절 구조를 통째로 무시하고 기초 프롬프트를 베꼈고,
사용자의 인물이 `professional soccer player` 가 됐다.

고친 방법 — 헤더 목록을 **맨 앞에** 두고 이렇게 못 박는다.

- "한 문단으로 답하지 말 것. BASE 를 그대로 베끼지 말 것"
- "BASE 의 **주제는 버린다. 그게 이 작업의 요점이다**"
- 비율은 "RATIO 에 주어진 문자열 그대로" — 안 그러면 7절에서 조용히 빠진다

### 결과를 검사하고 한 번 다시 시킨다

신원 고정 · DO NOT · 비율이 빠졌는지 코드가 본다. 빠지면 무엇이 빠졌는지
알려 주고 **한 번만** 다시 시킨다. 신원 고정이 빠진 프롬프트는 이 앱에서
쓸모가 없다 — 조용히 건네지 않는다. → `aikit/lib/prompts/generate.ts`

### 실측 (2026-09-18)

실제 사진으로 끝까지 태워 확인했다. 절 구조 유지 · 신원 고정 · 미화 금지 ·
데님 재킷/안경/검정 셔츠 전달 · 잘린 다리 재구성 안내 · 비율 4:5 ·
사진 속 문자 `Genspark` 를 위치까지 그대로. **1회 약 $0.008**(사진 2장).

## A-2. 프롬프트 고르기·맞추기 *(정정 전 기록)*

태그와 프롬프트 라이브러리를 받아 **3~5개를 고르고 사진에 맞게 손본다.**

- 모델: `OPENAI_MODEL` (채팅용 · 저렴한 쪽)
- `response_format: { type: "json_object" }` · `temperature: 0.4`

```
You adapt existing image-generation prompts to one specific photograph.

You are given:
- TAGS: structured tags describing the user's photo
- CANDIDATES: prompts from our library, each with id and text

For each of the 3 to 5 best candidates:
- Keep the candidate's structure, lighting language and camera language.
- Replace only the subject, wardrobe, setting and colour words so they
  match TAGS. Do not invent details TAGS does not support.
- Never add a named person, brand, logo or copyrighted character.
- Never describe anyone's race, age or nationality.
- Keep the adapted prompt under {MAX_CHARS} characters.
- Write one short Korean sentence saying what this one is good for.

Rank by how well the candidate's composition fits TAGS.framing and
TAGS.composition. A poster prompt needs negative space; do not rank it
first for a close-up.

Output JSON only:
{"picks":[{"sourceId":"...","title":"...","why":"...","prompt":"..."}]}
```

- `{MAX_CHARS}` 는 코드가 넣는다. 아래 "길이 예산" 참고
- `sourceId` 를 반드시 돌려받아야 **CC BY 4.0 출처 표기**를 붙일 수 있다.
  이건 선택이 아니라 라이선스 조건이다 → [[AIKit]]

## A-3. 대화형으로 다듬기

"더 밝게" · "포스터 말고 인물사진으로" 같은 요청을 받아 고친다.

```
You revise one image-generation prompt according to the user's request.

- Change only what the request asks for. Keep every other line intact.
- Never drop the identity-preservation lines or the DO NOT block.
- If the request would make the prompt exceed {MAX_CHARS}, shorten the
  scene description first, never the identity or typography rules.
- If the request asks for a real person, a brand, a logo or a known
  character, refuse that part in Korean and revise the rest.

Output JSON only:
{"prompt":"...","changed":"한 줄 한국어 설명"}
```

`changed` 를 받아 화면에 보여 주면 **무엇이 바뀌었는지** 사용자가 안다.
[[AI 채팅 패턴]] 의 되묻기와 같은 결이다.

# B. 사용자에게 돌려주는 이미지 생성 프롬프트

## ⚠️ 이 앱은 러닝 앱이 아니다

아래 1번이 러닝이라서 오해하기 쉽다. **러닝은 파일럿 한 건일 뿐이다.**

사용자 흐름은 이렇다 —

```
사진을 올린다  →  원하는 분위기를 고른다  →  그 분위기의 프롬프트를 받는다
```

**고르는 축은 소재가 아니라 분위기다.** "러닝 사진용"이 아니라 "시네마틱하게 /
필름 느낌으로 / 흑백 다큐로". 같은 사진이 분위기에 따라 전혀 다른 결과가 된다.

그래서 라이브러리도 **분위기로 묶는다.** 아래 어휘를 쓴다.

### 분위기 어휘 (`mood`)

| 값 | 한국어 | 결 |
|---|---|---|
| `cinematic` | 시네마틱 | 낮은 채도 · 와이드 · 영화 스틸 |
| `editorial` | 화보 | 잡지 · 정제된 조명 · 여백 |
| `film` | 필름 | 그레인 · 색 바램 · 35mm |
| `vintage` | 빈티지 | 70~90년대 · 노랑끼 · 낡은 질감 |
| `neon_night` | 네온 야경 | 도시 · 반사 · 강한 색광 |
| `soft_daylight` | 부드러운 낮광 | 창가 · 확산광 · 파스텔 |
| `monochrome` | 흑백 | 강한 대비 · 다큐 |
| `dreamy` | 몽환 | 블룸 · 안개 · 얕은 심도 |
| `bold_graphic` | 강한 그래픽 | 포스터 · 큰 타이포 · 원색 |
| `minimal` | 미니멀 | 단색 배경 · 여백 · 군더더기 없음 |
| `illustration` | 일러스트 | 손그림 · 수채 · 애니 |
| `retro_print` | 레트로 인쇄 | 리소그래프 · 하프톤 · 종이 질감 |

- 이 목록의 원본은 `lib/prompts/vocab.ts` 다. A-1 태그와 **같은 파일을 본다**
- 프롬프트 하나에 `mood` 는 **하나**다. 둘 이상이면 프롬프트를 쪼갠다
- 소재(`activity` · `suitable_for`)는 **보조 필터**다. 축이 아니다
- 어휘를 늘릴 때는 화면의 칩 개수를 먼저 본다. 12개가 한 화면에 들어가는 상한이다

⚠️ **소재별로 프롬프트를 쌓지 않는다.** "러닝용 / 등산용 / 카페용"으로 가면
경우의 수가 무한히 늘고, 정작 사용자는 소재가 아니라 **느낌**을 고른다.
1번이 러닝인 것은 첫 사진이 러닝 사진이었기 때문이지 제품 방향이 아니다.

## 여덟 토막 골격

러닝 포스터를 쓰면서 자리 잡은 구조다. **순서가 의미가 있다** — 모델이 뒤쪽을
덜 따르므로, 지켜야 할 것을 앞에 둔다.

```
0. ROLE      한 줄. 어떤 사람이 만드는 결과물인지
1. INPUTS    입력 이미지가 각각 무엇인지 (Image 1 = …, Image 2 = …)
2. TASK      한 줄. 무엇을 만드는지
3. SUBJECT   ⚑ 신원 고정. 바꾸지 말 것을 명시
4. POSE      자세와 카메라. 좌우는 쓰지 않는다
5. LIGHT     조명·분위기·배경
6. GRAPHIC   색 체계. 팔레트를 몇 개로 묶는다
7. TYPOGRAPHY 글자. 어디서 온 값인지 · 고치지 말 것
8. OUTPUT    비율 · 마감 · 품질
9. DO NOT    금지 목록. 마지막
```

**왜 이 순서인가**

- 3(신원)이 앞에 있어야 얼굴이 덜 바뀐다. 뒤로 가면 조용히 무시된다
- 9(DO NOT)는 맨 뒤가 맞다. 앞에 두면 금지어를 오히려 그린다
- 4에서 **`left` / `right` 를 쓰지 않는다.** 모델이 좌우를 뒤집고, 뒤집힌 채로
  "지시를 지켰다"고 판단한다. `one knee up, the opposite hand down` 처럼 **상대 관계**로 쓴다

## B-1. 파일럿 — `neon_night` × 포스터

**2026-09-17 작성. 이미지 모델에 돌린 적 없다.**
사용자가 준 사진(야간 거리 · 스프린터 크라우치 · 점자블록)을 보고 만든 **첫 프롬프트**다.

이 앱에서 처음 만들어 본 것이라 골격이 여기서 나왔다.
**러닝 전용으로 두지 않는다** — `mood: neon_night` 의 대표 프롬프트로 일반화한다.
아래 "일반화하는 법" 참고.

```
ROLE: Editorial sports poster art director.

INPUTS
- Image 1: photograph of the runner (reference for face, body, outfit, pose).
- Image 2: screenshot of a running record (distance, time, average pace).

TASK: Produce a single vertical night-running poster.

1. SUBJECT — IDENTITY LOCK
Recreate the person from Image 1 exactly: same facial structure, same
glasses, same hair volume and texture, same lean athletic build. Do not
beautify, slim, re-age, or alter ethnicity. Keep the outfit exactly:
black sleeveless running top, lavender split shorts, black crew socks,
mint-grey running shoes, sports watch on the wrist.

2. POSE & FRAMING
Keep the low sprinter's crouch from Image 1 — one knee driven up with
that foot planted, the other knee dropped low, the opposite hand's
fingertips pressed to the pavement, torso coiled forward, head turned in
profile with the gaze locked off-frame. Ground-level camera, 35mm lens,
slight upward tilt so the figure reads heroic. Full body in frame,
nothing cropped at hands or feet. Subject occupies the lower two-thirds,
open dark space above.

3. LIGHT & ATMOSPHERE
Deep-night empty urban street. A single hard key light from the front,
like a direct camera flash, carving sharp specular highlights along the
shoulders, forearm and calves; everything beyond three metres falls into
near-black. Cold teal-to-black background gradient, faint sodium-orange
streetlight bokeh, humid summer haze. Sweat sheen on the skin. Background
slightly motion-blurred, subject tack sharp.

4. GRAPHIC ACCENT
Carry the safety-yellow of the Korean tactile paving from Image 1 into
the design system: keep the ribbed yellow paving under the hand and foot
as the ONLY saturated colour in the photograph, and reuse that exact
yellow for the typographic accents. Restrict the whole palette to black,
cold teal, off-white, and that yellow.

5. TYPOGRAPHY — SOURCED FROM IMAGE 2
Read the distance, total time and average pace from Image 2 and
transcribe them EXACTLY. Do not invent, round, estimate, or alter any
number. Set them as a stat block down the right edge in a condensed
grotesque (Archivo Condensed / Helvetica Now Condensed feel):
- Distance as the hero figure — very large, yellow.
- Time and pace below in off-white small caps, separated by hairline
  rules, each with a tiny label (DISTANCE / TIME / PACE).
- One short all-caps headline top-left in off-white: "NIGHT SHIFT".
Strict grid, generous negative space. No drop shadows, no glow, no
outlines on type.

6. OUTPUT
Vertical 4:5 poster. Photoreal sports-editorial finish, fine 35mm grain,
no border, high contrast, magazine-print quality.

DO NOT: no additional people, no race bib, no brand logos or swooshes, no
watermark, no lens flare, no HDR halo, no plastic skin smoothing, no
distorted or extra fingers, no garbled or duplicated text.
```

### 바꿔 끼우는 자리

라이브러리에 넣을 때 아래를 변수로 판다.

| 변수 | 기본값 | 비고 |
|---|---|---|
| `{HEADLINE}` | `NIGHT SHIFT` | 코스명·거리도 들어간다 |
| `{RATIO}` | `4:5` | 스토리는 `9:16` |
| `{ACCENT_COLOR}` | 사진에서 뽑은 색 | `TAGS.color.dominant` 에서 |
| `{OUTFIT}` | 사진에서 | `TAGS.subject.wearing` 에서 |
| `{SCENE}` | 3절 전체 | 낮 사진이면 **통째로 교체**한다 |

⚠️ **낮 사진에 3절을 그대로 쓰면 낮을 밤으로 바꿔 버린다.**
`TAGS.scene.time_of_day` 로 분기한다.

한글 타이포가 필요하면 5절에 한 줄을 더한다 —
`in a condensed Korean sans-serif (Pretendard feel)`

### 일반화하는 법 — 소재를 들어낸다

위 프롬프트에서 **러닝에 묶인 것은 세 군데뿐**이다. 들어내면 `neon_night` 의
범용 야간 포스터가 된다.

| 자리 | 러닝 전용 | 일반형 |
|---|---|---|
| 1절 옷 | `running top` `split shorts` `running shoes` | `{OUTFIT}` — `TAGS.subject.wearing` 에서 |
| 2절 자세 | `sprinter's crouch` 서술 | `{POSE}` — `TAGS.subject.pose` 에서 |
| 5절 | 거리·시간·페이스 | `{STAT_BLOCK}` — 없으면 절 전체를 뺀다 |

나머지(조명 · 색 체계 · 카메라 · 출력 · DO NOT)는 소재와 무관하다. **그게 분위기다.**

다른 분위기의 프롬프트를 만들 때도 같은 방식으로 한다 —
**3·5·6절이 분위기를 만들고, 1·2·7절이 소재를 받는다.**

## 반복해서 깨지는 것 다섯

### ① 기록 숫자를 틀린다 — **코드로 푼다**

`DO NOT invent, round, estimate` 를 넣어도 이미지 모델은 숫자를 틀린다.
글자를 그리는 것이지 옮겨 쓰는 게 아니기 때문이다.

**앱에서는 이미지 모델에 숫자를 맡기지 않는다.**

```
기록 스크린샷 → OCR/Vision 으로 추출 → 사용자 확인 → 오버레이로 합성
```

추출값은 [[OpenAI Vision 추출 패턴]] 의 **검토 화면**을 그대로 거친다.
이미지 모델에는 "글자 자리를 비워 두라"고 시키는 편이 낫다.

### ② 자세를 일반적인 러닝 자세로 되돌린다

크라우치·점프 같은 특이 자세는 모델이 평균으로 끌어당긴다. 안 되면 2절을 —

```
Preserve the exact body pose from Image 1 pixel-for-pixel;
change only the lighting and background.
```

### ③ 얼굴이 미화된다

`Do not beautify, slim, re-age` 를 넣어도 턱선이 깎이고 피부가 매끈해진다.
1절을 맨 앞에 두는 것이 지금까지 가장 효과적인 방어다.

### ④ 좌우가 뒤집힌다

4절 설명대로 **상대 관계로만** 쓴다. `left`/`right` 를 쓰지 않는다.

### ⑤ 글자가 깨진다

한글은 특히 심하다. 그래서 ①의 오버레이 합성이 결국 맞는 답이다.
이미지 안 글자는 **영문 짧은 헤드라인 하나까지**로 줄인다.

## 길이 예산

딥링크가 프롬프트 길이를 제약한다 → [[AIKit]]

```
위 러닝 프롬프트          약 2,400자
URL 인코딩 후            약 4,300자  (한글 섞이면 더)
도구 제공자들의 상한       4,000자
```

- 라이브러리에 **`charCount` 를 저장**해 둔다. 매번 세지 않는다
- A-2 · A-3 의 `{MAX_CHARS}` 를 대상 서비스별로 넣는다
- 상한을 넘으면 **딥링크 버튼을 숨기고 복사만 남긴다**
- 줄일 때는 장면 묘사부터 줄인다. **신원 고정과 타이포 규칙은 마지막까지 남긴다**

## 라이브러리 저장 형태

`aikit` DB. HF `Goku-OpenLab` 스키마를 우리 쪽으로 옮긴 모양이다.
**필드 매핑·큐레이션·적재 스크립트는 [[프롬프트 데이터 적재 지침]] 에 있다.**

```
prompts   _id · slug · title · body · vars[] · charCount
          · mood            ← 고르는 축. 하나만
          · tags{} (A-1 과 같은 어휘)
          · origin(dataset|authored) · sourceId · sourceLink · license
          · locale · verified(bool) · verifiedAt · createdAt
```

- `license` 와 `sourceLink` 는 **비워 두지 않는다.** CC BY 4.0 이 표기를 요구한다
- `origin: authored` 는 우리가 쓴 것. 러닝 프롬프트가 여기 들어간다
- **`verified`** 는 실제로 이미지를 만들어 확인한 것만 `true`.
  지금은 전부 `false` 다. 화면에서 검증분을 위로 올린다
- `vars` 는 위 "바꿔 끼우는 자리" 표
