# 피검사 지식베이스

FitLog `Blood` 탭. 피검사 결과지를 읽고 **무엇을 바꾸면 되는지까지** 데이터로 갖는다.
2026-09-05에 만들었다. 진료지침을 먼저 확인하고 설계를 세 군데 고쳤다.

## ⚠️ "정상수치"는 두 종류다 — 이 노트의 핵심

결과지 한 장에 두 기준이 나란히 인쇄되는데 만들어진 방식이 다르다.

| | 참고구간 (reference interval) | 임상 결정치 (clinical decision limit) |
|---|---|---|
| 출처 | 건강인 분포의 가운데 95% | 위험이 올라가는 선을 본 연구 |
| 나이·성별·체격 | **탄다** | **안 탄다** |
| 검사실마다 | 다르다 | 같다 |
| 저장 위치 | 기록마다 (인쇄값 그대로) | 카탈로그에 고정 |

섞으면 앱이 **정확히 반대로 말한다** — "나이 있으시니 콜레스테롤 조금 높아도 괜찮다".
중년 이후 콜레스테롤 *분포*는 올라가지만 치료 목표는 그래서 더 낮아진다.

그래서 `referenceInterval`(기록)과 `decisionLimits`(지식)를 **다른 필드**로 뒀다.

## 나이·성별·체격 보정은 일부 항목에만

근거가 확인된 것만 넣는다. 없는 항목은 보정하지 않는다.

| 항목 | 요인 | 내용 |
|---|---|---|
| TSH | 나이 | 분포 전체가 위로 이동. 97.5백분위가 20세 3.56 → 80세 7.49 μIU/mL |
| Creatinine · eGFR | 성별·근육량 | 추정식은 나이·성별만 넣고 **근육량은 안 넣는다** |
| Hb · Hct · RBC | 성별 | 결과지도 성별 기준으로 인쇄 |
| ALP | 나이 | 성장기 급증, 성인 후 안정 |
| Uric acid | 성별 | 남 > 여, 여성은 폐경 후 상승 |
| CPK | 성별·근육량·최근 운동 | 검사 전 운동 여부를 모르면 해석 불가 |
| LDL · HbA1c | **없음** | 목표는 위험도로 정한다. 나이로 완화하지 않는다 |

## 인바디와 겹쳐야 보이는 것 — 이 앱만 할 수 있다

피검사만 보는 앱은 많다. FitLog에는 **같은 사람의 체성분이 있다.**

- **크레아티닌↑ / eGFR↓ + 골격근량 많음** — 추정식은 모두 평균 근육량을 가졌다고 가정한다.
  근육이 많으면 신장 기능이 실제보다 낮게 나온다. 시스타틴 C 검사를 안내(진료 판단)
- **CPK↑ + 근력운동** — 며칠 쉬고 재검하면 구분된다
- **ALT↑ + 내장지방·체지방↑** — 같은 방향. 운동이 체중 감소 없이도 ALT를 낮춘 근거가 있다
- **Hb·Hct↑ + 체수분↓** — 탈수로 농축돼 보일 수 있다

**맥락 제시까지만 한다.** 원인을 단정하지 않는다.

> 인바디는 결과지에 표준범위가 인쇄되지 않는 항목이 있다(내장지방레벨).
> 교차 규칙에 `inbodyThreshold`를 두지 않으면 그런 항목은 **영영 성립하지 않는다.**

## 권고에는 근거 등급이 필수다

`Guidance.evidence` 없이는 항목을 추가하지 않는다. 근거가 센 조언과 약한 조언이
같은 얼굴로 나오면 사용자는 구분할 수 없고, 앱은 자신 있게 틀린 말을 한다.

```
A 강함        지침의 강한 권고 또는 일관된 RCT
B 보통        지침의 조건부 권고 또는 메타분석
C 약함        흔히 하는 말이지만 시험에서 확인되지 않음
D 권하지 않음  지침이 이득 없음으로 분류
```

**등급 D도 지우지 않는다.** "중성지방 높으면 오메가3" 같은 말은 사용자가 이미 듣고 온다.
앱이 침묵하면 그 말이 그대로 남는다.

화면에서 조언마다 **"무엇을 근거로 한 말인가요?"** 를 펼치면 연구 설계·대상·한계까지
읽을 수 있다(`Guidance.basis`). 신뢰는 결론이 아니라 출처를 보여줄 때 생긴다.

### 조사하며 알게 된 것

- **일반 어유(오메가3) 보조제는 2026 ACC/AHA/NLA에서 Class III(이득 없음).**
  심혈관 사건 25% 감소는 **처방약 icosapent ethyl**(REDUCE-IT) 이야기다. 옮겨 쓰면 안 된다
- **2024 내분비학회는 건강한 성인에게 비타민D 검사 자체를 권하지 않는다.**
  결과지는 30 ng/mL 기준으로 '부족'을 찍는데 지침은 목표 수치를 정하지 않는다 —
  **검사실 표시와 지침이 어긋나는 구간이다.** 어느 쪽이 맞다고 앱이 정하지 않는다
- **퓨린 제한은 RCT에서 요산을 못 낮췄다.** 식이 지식만 늘었다. ACR도 조건부 권고다
- 반대로 근거가 센 것 — **체중이 안 줄어도 운동만으로** ALT −3.30 U/L, 중성지방 SMD −0.59

### 영양제 규칙

**검사로 결핍이 확인된 항목에만.** 수치가 조금 높거나 낮다는 이유로 붙이지 않는다.
용량·복용법은 말하지 않고 진료를 권한다. 전문의약품은 언급하지 않는다.

## RAG는 손으로 쓰지 않고 생성한다

`lib/bloodRagChunks.ts`가 카탈로그·권고에서 청크를 만든다(구획별 8개 + 개념 3개).

손으로 쓴 요약은 **반드시 갈라진다** — 항목을 추가하거나 등급을 고쳤을 때 화면은 새
내용을, 상담사는 옛말을 한다. 같은 앱이 같은 질문에 두 가지로 답한다.

생성이라 **카탈로그에 항목을 넣으면 상담사도 그 자리에서 안다.**

> 인바디 청크(`chatRagDocuments.ts`)는 아직 손으로 쓴 5개다. 이미 갈라져 있다 —
> `FIELDS`는 36개인데 상담사는 체지방·골격근·체수분·기초대사량 4개만 안다.

## 기록 저장

| 원칙 | 인바디와 같음 | 다른 점 |
|---|---|---|
| 날짜당 1건 | ✓ `userId + testedDate` | |
| 검토 후 저장 | ✓ 자동 저장 안 함 | |
| 모르는 항목은 `etc`로 | ✓ | |
| 값 구조 | | **고정 필드가 아니라 결과 배열** — 회차마다 패널이 다르다 |
| 참고치 | 표준범위를 함께 저장 | **원문(`refText`)과 판정(`flag`)까지** 저장 |

참고치를 기록마다 저장하는 이유 — 검사실이 기준을 바꾸면, 카탈로그 값으로 다시 그릴 때
**그때 본 화면이 재현되지 않는다.**

판정은 결과지의 H/L 표시를 **그대로 따른다.** 검사실이 자기 기준을 우리보다 잘 안다.

### 검산으로 오인식 잡기

인바디의 합계 규칙처럼, 피검사에도 계산으로 확인되는 관계가 있다.

- 총콜레스테롤 ≈ HDL + LDL + TG/5 (Friedewald, TG 400 미만)
- MCHC = Hb ÷ Hct × 100 · MCH = Hb ÷ RBC × 10 · MCV = Hct ÷ RBC × 10
- 알부민 ≤ 총단백
- eAG = 28.7 × HbA1c − 46.7

실제 결과지 2장(73줄)으로 확인 — 카탈로그 매칭 73/73, 검산 경고 0건.

## 화면

`핵심 4축 → 이번에 벗어난 항목 → 구획별 전 항목 → 등록된 결과지`
인바디와 같은 순서다. **해석이 먼저, 원본이 나중.**

**4축은 레이더로 그리지 않았다.** 레이더는 축들이 같은 척도로 읽힌다는 인상을 주는데,
피검사는 단위도 방향도 제각각이다(ALT는 낮을수록, eGFR은 높을수록 좋다). 정규화해
한 그림에 얹으면 그림은 그럴듯한데 읽는 사람이 틀린 결론을 얻는다.
**항목마다 자기 눈금을 가진 막대**가 정직하다.

그 아래 "이번에 벗어난 항목"은 회차마다 구성이 바뀌는 대신 볼 것이 분명해진다.

## 함정

### 개발 서버가 켜진 채로 빌드하지 말 것

같은 `.next`를 쓰면서 `Cannot find module './5611.js'`로 서로를 깨뜨린다.
`NEXT_DIST_DIR=.next-build npm run build` 로 따로 쌓되, **끝나면
`tsconfig.json`과 `next-env.d.ts`를 되돌린다** — Next가 타입 경로를 그 폴더로 고쳐 쓴다.

### 소유자 확인을 빠뜨리지 말 것

`/api/blood/[id]`의 GET·PATCH·DELETE는 `{_id, userId}`를 함께 조회한다.
id만 보고 지우면 남의 기록 id를 넣어 지울 수 있다. (인바디 라우트가 원래 이렇게 되어 있었고,
새로 만들면서 빠뜨렸다가 맞췄다.)
