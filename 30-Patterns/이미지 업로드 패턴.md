# 이미지 업로드 패턴

Vercel Functions는 **요청 본문 4.5MB**를 넘으면 함수 코드에 닿기도 전에
`FUNCTION_PAYLOAD_TOO_LARGE`로 잘린다. 라우트 안의 크기 검사는 의미가 없다.

앱마다 성격이 달라 해법도 다르게 갔다. **목적지를 보고 고른다.**

## 선택 기준

| 파일의 목적지 | 방법 | 적용 |
|---|---|---|
| 스토리지에 **원본 보관** | 사전 서명 URL로 브라우저 → R2 직접 PUT | [[Ignite]], klead |
| 외부 API로 **분석만** | 업로드 전 클라이언트 축소 | [[SnapWord]], [[FitLog]] |
| 클라이언트가 **이미 가공**해서 만든 이미지 | 생성 단계에서 해상도 제한 | [[SnapNote]] |

## ① 사전 서명 직접 업로드

파일이 서버를 거치지 않으므로 크기 제한과 무관해진다.

1. `POST /api/.../sign` — 관리자 검증 후 `getSignedUrl(PutObjectCommand)` 발급 (본문은 JSON 수백 바이트)
2. 브라우저가 그 URL로 직접 `PUT` (XHR을 쓰면 진행률 표시 유지)
3. **R2 버킷 CORS 필수** — `PUT/GET/HEAD` + 허용 Origin

### 함정: SDK 기본 체크섬

AWS SDK v3는 기본으로 CRC32 체크섬을 계산하는데, **사전 서명 시점(본문이 없는 시점)의
빈 본문 체크섬**이 URL에 박힌다. 실제 업로드를 R2가 400으로 거부한다.

```ts
new S3Client({
  // ...
  requestChecksumCalculation: "WHEN_REQUIRED",
  responseChecksumValidation: "WHEN_REQUIRED",
})
```

`ContentLength`를 서명에 포함하면 신고한 크기와 실제 파일이 다를 때 R2가 거부한다(무결성 확보).

### 함정: R2 토큰 권한

버킷 CORS를 API로 설정하려면 **Admin Read & Write** 토큰이 필요하다.
오브젝트 읽기/쓰기 전용 토큰은 `AccessDenied`가 난다 → Cloudflare 대시보드에서 직접 설정.

## ② 업로드 전 클라이언트 축소

`createImageBitmap(file, { imageOrientation: "from-image" })` → canvas → `toBlob`.
EXIF 회전이 반영되고, 재인코딩 시 EXIF가 사라져 이중 회전도 없다.

- Vision 입력이면 **긴 변 2000px / JPEG 0.82** 로 충분하다.
  OpenAI Vision은 그 이상 해상도에서 정확도 이득이 거의 없고, 업로드도 토큰 비용도 준다
- 결과가 원본보다 크면 원본을 그대로 쓴다

## ③ 생성 단계에서 해상도 제한

SnapNote는 사진을 **임계값 이진화**해서 PNG로 만든다. 이진화는 잡음을 대량으로 만들어
원본 해상도에서는 PNG가 수 MB까지 부푼다.

- 긴 변 2400px 기준으로 이진화
- 결과가 3.5MB를 넘으면 **1800 → 1400px로 자동 재인코딩**
- **형식은 PNG 유지** — 이진 이미지는 넓은 단색 영역 덕에 JPEG보다 PNG가 작고 깨끗하다

사용자가 용량 오류를 만나는 경우를 사실상 없앤다.

## 공통

- 서버 쪽 상한도 4MB 정도로 맞춰 메시지를 일관되게 한다
- 업로드 라우트에 `export const maxDuration = 60`
- 진행률은 `fetch`가 아니라 **XHR**로 (`xhr.upload.onprogress`)
