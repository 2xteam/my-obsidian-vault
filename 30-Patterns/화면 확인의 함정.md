# 화면 확인의 함정

AI가 브라우저 도구로 화면을 확인할 때 **"있다"와 "보인다"는 다르다.**
2026-09-08 jangmini 에서 이걸로 오판했다 → [[jangmini]]

## ⚠️ DOM 존재만 보고 정상이라고 판단하지 않는다

햄버거 메뉴를 만들고 확인했을 때 —

```
read_page  → 링크 5개가 접근성 트리에 다 보인다
find       → button "메뉴 열기" 를 찾는다
JS         → aria-expanded: "true", nav 존재, 링크 5개
```

**전부 통과했는데 화면에는 아무것도 없었다.**

```js
getComputedStyle(nav).opacity   // "0"
getComputedStyle(nav).transform // "matrix(0.98, 0, 0, 0.98, 0, -6)"
```

등장 애니메이션의 **시작 상태에 멈춰 있었다.** `initial={{opacity:0}}` 에서
`animate` 가 끝까지 가지 않은 것이다.

### 확인할 때 함께 재는 것

```js
const el = document.querySelector(선택자);
const cs = getComputedStyle(el);
const r  = el.getBoundingClientRect();
({
  opacity: cs.opacity,        // "0" 이면 안 보인다
  visibility: cs.visibility,  // "hidden"
  display: cs.display,        // "none"
  w: r.width, h: r.height,    // 0 이면 접혀 있다
  보이나: cs.opacity !== '0' && cs.visibility === 'visible' && r.width > 0,
});
```

스크린샷도 믿을 수 있는 증거지만 **브라우저 패널의 스크린샷은 DOM 상태보다
늦게 갱신될 때가 있다** (jangmini 에서 여러 번 겪었다). 스크린샷이 이상하면
computed 값을 재서 교차 확인한다.

## ⚠️ 가시성을 애니메이션에 의존시키지 않는다

위 문제의 근본 원인이다. **기본 상태가 "안 보임"이고 애니메이션이 "보임"으로
데려가는 구조**는, 애니메이션이 어떤 이유로든 실행되지 않으면 요소가 사라진다.

같은 증상을 두 방식에서 겪었다.

| 방식 | 시작 상태 |
|---|---|
| `AnimatePresence` + `motion.div` 의 `initial={{opacity:0}}` | opacity 0 |
| tw-animate-css 의 `animate-in fade-in` | opacity 0 |

실행되지 않는 이유는 여러 가지다 — 개발 중 HMR 재마운트, `prefers-reduced-motion`,
`AnimatePresence` 의 key 누락, 라이브러리 중복(`framer-motion` 과 `motion` 을
함께 들고 있는 저장소가 있다).

**대응**

- **꼭 보여야 하는 것**(메뉴 · 다이얼로그 · 에러 문구 · 폼)에는 등장
  애니메이션을 두지 않는다. 기본 상태가 보이는 상태여야 한다
- 애니메이션은 **장식**으로만 쓴다 — 없어도 기능이 성립하는 자리
- 굳이 넣는다면 `@media (prefers-reduced-motion: reduce)` 에서 **끝 상태로
  바로 가게** 한다. 시작 상태에 멈추게 두지 않는다

## ⚠️ lazy 이미지는 "안 뜬다"와 "아직 안 불렀다"가 똑같이 보인다

FitLog 프로젝트 페이지의 갤러리 5장이 `naturalWidth 0x0` 이라 실패로 봤다.
`src` 는 정확했고 4xx 도 없었다. 원인은 단순히 **아직 요청이 안 나간 것**이다
— `loading="lazy"` 라 뷰포트에 들어오기 전에는 안 부른다.

내가 오판한 이유는 `performance.getEntriesByType('resource')` 가 빈 배열인 걸
"요청이 실패했다"로 읽었다는 데 있다. **빈 배열은 실패가 아니라 무기록이다.**

**구분법**

| 보이는 것 | 실패 | 아직 안 부름 |
|---|---|---|
| 네트워크 로그 | 4xx/5xx 항목이 있다 | 항목이 **없다** |
| `img.complete` | `true` (naturalWidth 0) | `false` |

`complete === false` 면 기다리거나 스크롤해서 발동시킨 뒤 다시 본다. 실제로
스크롤 후에는 5장이 `w=640` 으로 전부 200 이었다.

## 로그인이 필요한 화면은 사용자가 찍고, 파일로 받는다

로그인 뒤 화면을 캡쳐하려면 그 세션의 쿠키가 필요하다. 그런데

- 크롬이 켜져 있으면 **프로필 디렉터리가 잠긴다** → `--user-data-dir` 로
  실제 프로필을 못 쓴다
- 쿠키 저장소를 임시 프로필로 **복사하는 것은 자격 증명 복사**다. 자동
  승인 대상이 아니고, 우회할 일도 아니다
- 브라우저 도구로 찍은 화면은 **대화에만 온다.** `claude-in-chrome` 의
  `save_to_disk` 는 이 확장 버전에서 경로를 돌려주지 않았다(2026-09-09)

그래서 **사용자가 찍고, 나는 파일을 찾아 쓴다.** 첨부한 이미지는 디스크에
남으므로 경로를 알면 그대로 R2 에 올릴 수 있다.

| 어디서 왔나 | 어디에 있나 |
|---|---|
| 데스크톱 앱에 붙여넣기(paste) | `%TEMP%\orca-paste-<epoch ms>-<uuid>.png` |
| `Win`+`PrtSc` · `Win`+`Shift`+`S` | `%USERPROFILE%\Pictures\Screenshots\` |
| 내가 `Read` 한 이미지 | `~/.claude/image-cache/<id>/<n>.png` |

⚠️ **한 메시지에 여러 장을 붙이면 전부 남지는 않는다.** 4장을 받았는데
`image-cache` 에는 마지막 1장만 있었다. 확실한 것은 `Pictures\Screenshots`
쪽이다 — 사용자가 캡쳐 키로 찍으면 장마다 파일이 생긴다.

⚠️ **파일을 쓰기 전에 반드시 열어 본다.** 전체 화면 캡쳐에 편집기의
`.env.local` 이 열려 있어 시크릿이 그대로 보인 일이 있었다. 게시는 배포다.
→ [[jangmini]]

로그인 **전** 화면은 헤드리스로 얼마든지 찍는다:

```
chrome.exe --headless=new --disable-gpu --hide-scrollbars   --window-size=1280,900 --virtual-time-budget=9000   --screenshot="절대경로.png" "https://…"
```
