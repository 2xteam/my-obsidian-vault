# 화면 확인의 함정

AI가 브라우저 도구로 화면을 확인할 때 **"있다"와 "보인다"는 다르다.**
2026-09-08 jangmini 에서 이걸로 오판했다 → [[jangmini]]

## ⚠️ DOM 존재만 보고 정상이라고 판단하지 않는다

햄버거 메뉴를 만들고 확인했을 때 —

```
read_page  → 링크 5개가 접근성 트리에 다 보인다
find       → button "메뉴 열기" 를 찾는다
JS         → aria-expanded: "true", nav 존재, 링크 5개
```

**전부 통과했는데 화면에는 아무것도 없었다.**

```js
getComputedStyle(nav).opacity   // "0"
getComputedStyle(nav).transform // "matrix(0.98, 0, 0, 0.98, 0, -6)"
```

등장 애니메이션의 **시작 상태에 멈춰 있었다.** `initial={{opacity:0}}` 에서
`animate` 가 끝까지 가지 않은 것이다.

### 확인할 때 함께 재는 것

```js
const el = document.querySelector(선택자);
const cs = getComputedStyle(el);
const r  = el.getBoundingClientRect();
({
  opacity: cs.opacity,        // "0" 이면 안 보인다
  visibility: cs.visibility,  // "hidden"
  display: cs.display,        // "none"
  w: r.width, h: r.height,    // 0 이면 접혀 있다
  보이나: cs.opacity !== '0' && cs.visibility === 'visible' && r.width > 0,
});
```

스크린샷도 믿을 수 있는 증거지만 **브라우저 패널의 스크린샷은 DOM 상태보다
늦게 갱신될 때가 있다** (jangmini 에서 여러 번 겪었다). 스크린샷이 이상하면
computed 값을 재서 교차 확인한다.

## ⚠️ 가시성을 애니메이션에 의존시키지 않는다

위 문제의 근본 원인이다. **기본 상태가 "안 보임"이고 애니메이션이 "보임"으로
데려가는 구조**는, 애니메이션이 어떤 이유로든 실행되지 않으면 요소가 사라진다.

같은 증상을 두 방식에서 겪었다.

| 방식 | 시작 상태 |
|---|---|
| `AnimatePresence` + `motion.div` 의 `initial={{opacity:0}}` | opacity 0 |
| tw-animate-css 의 `animate-in fade-in` | opacity 0 |

실행되지 않는 이유는 여러 가지다 — 개발 중 HMR 재마운트, `prefers-reduced-motion`,
`AnimatePresence` 의 key 누락, 라이브러리 중복(`framer-motion` 과 `motion` 을
함께 들고 있는 저장소가 있다).

**대응**

- **꼭 보여야 하는 것**(메뉴 · 다이얼로그 · 에러 문구 · 폼)에는 등장
  애니메이션을 두지 않는다. 기본 상태가 보이는 상태여야 한다
- 애니메이션은 **장식**으로만 쓴다 — 없어도 기능이 성립하는 자리
- 굳이 넣는다면 `@media (prefers-reduced-motion: reduce)` 에서 **끝 상태로
  바로 가게** 한다. 시작 상태에 멈추게 두지 않는다
