# 옵시디언 사용 규칙

이 볼트를 일관되게 유지하기 위한 최소한의 약속. 규칙이 많으면 안 지키게 되니 짧게 둔다.

## 폴더 — 얕게, 5~6개만

2026년 기준 권장은 **깊은 폴더 대신 링크와 MOC**다. 3~4단계를 넘어가면 이미 너무 깊다.

```
00-Meta       볼트 자체에 대한 것 (이 문서, AI 협업 규칙)
10-Projects   서비스·앱별 정보
20-Design     디자인 시스템, 페이지 패턴, 카피 가이드
30-Patterns   반복해서 쓰는 개발 패턴
40-Infra      도메인·DB·스토리지·배포
Templates     새 노트 틀
```

숫자 접두사는 정렬용이다. 새 카테고리가 필요하면 `50-`, `60-`으로 늘린다.
**하위 폴더는 만들지 않는다.** 분류가 더 필요하면 태그나 MOC로 푼다.

## 파일 이름

- 사람이 읽는 이름을 그대로 쓴다: `결쩜사 디자인 시스템.md`, `FitLog.md`
- 날짜가 들어가면 `YYYY-MM-DD` 형식
- 이름이 곧 링크(`[[FitLog]]`)이므로 **이름을 바꾸면 옵시디언이 링크를 자동 갱신**한다

## 프로퍼티(YAML 프론트매터)

모든 노트 맨 위에 최소한 이만큼 둔다.

```yaml
---
title: 노트 제목
type: project | pattern | design-system | page-pattern | infra | meta | moc
tags: [분류, 태그]
updated: 2026-09-02
---
```

프로젝트 노트는 `status` `domain` `repo` `local` `branch` `db`를 추가한다.
`local`은 로컬 클론 경로 — AI가 작업할 때 바로 찾아간다.

## 링크

- 다른 노트를 언급하면 **반드시 `[[대괄호]]`로 건다**. 나중에 그래프뷰에서 관계가 보인다
- 아직 없는 노트를 링크해도 된다 — "쓸 만한 주제"라는 표시가 된다
- 각 폴더의 MOC 노트가 그 폴더의 목차 역할을 한다

## MOC (Map of Content)

폴더는 하나의 위치만 가지지만, 노트는 여러 MOC에 등장할 수 있다.
[[Home]]이 최상위 MOC이고, 각 폴더에 `... MOC` 노트를 둔다.

## 무엇을 적나

- **재현 가능해야 하는 것** — 디자인 토큰, 페이지 구조, 배포 절차
- **다시 밟기 싫은 함정** — 원인과 증상을 함께
- **결정과 그 이유** — "왜 이렇게 했는지"는 코드에 남지 않는다

## 무엇을 적지 않나

- 코드에서 바로 읽히는 것 (파일 목록, 함수 시그니처)
- 한 번 쓰고 버릴 임시 메모
- 비밀값 (API 키, 비밀번호, 연결 문자열) — **절대 넣지 않는다.** 공개 저장소다
