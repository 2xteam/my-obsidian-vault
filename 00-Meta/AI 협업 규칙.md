# AI 협업 규칙

Claude Code 등 AI에게 작업을 맡길 때 이 볼트를 어떻게 쓰는지에 대한 약속.

## 볼트 위치

```
저장소: https://github.com/2xteam/my-obsidian-vault
로컬:   C:\Dev\my-obsidian-vault
```

각 프로젝트 저장소의 `CLAUDE.md`가 이 경로를 가리킨다.
AI는 작업 시작 전에 해당 문서를 읽고, 끝나면 바뀐 사실을 볼트에 반영한다.

## 작업 시작 전에 읽을 것

| 작업 성격 | 먼저 읽을 노트 |
|---|---|
| 아무 작업이나 | 해당 프로젝트 노트 (`10-Projects/*.md`) |
| 배포·환경 변수·도메인 | [[Vercel 배포 패턴]] · [[도메인과 DNS]] |
| 이미지 업로드 | [[이미지 업로드 패턴]] |
| 로그인·회원·세션 | [[인증과 세션 공유]] |
| DB 연결 | [[MongoDB Atlas]] |
| 결쩜사 결의 페이지 제작 | [[결쩜사 디자인 시스템]] · [[결쩜사 페이지 패턴]] · [[결쩜사 카피 톤앤매너]] |
| 새 참고 사이트 분석 | [[레퍼런스 사이트 분석 방법]] |

## 작업이 끝나면 볼트를 갱신한다

다음이 바뀌었으면 **해당 노트를 고치고 `updated` 날짜를 올린다.**

- 도메인·DB·버킷·브랜치 같은 사실
- 새로 발견한 함정 (증상 + 원인 + 해결)
- 프로젝트 진행 상황 체크박스
- 새 디자인 토큰이나 컴포넌트 규칙

볼트 수정은 **별도 커밋**으로 남긴다. 코드 커밋과 섞지 않는다.

## 지켜야 할 것

- **비밀값을 볼트에 쓰지 않는다.** 공개 저장소다. 변수 이름까지만 적는다
- 사실과 계획을 구분한다. 계획은 체크박스(`- [ ]`)로 둔다
- 추측을 단정으로 쓰지 않는다. 확인하지 못한 것은 "확인 필요"로 남긴다
- 노트를 새로 만들기 전에 **기존 노트에 들어갈 자리가 있는지** 먼저 본다

## ⚠️ 개발 서버가 떠 있을 때 `npm run build` 를 돌리지 않는다

`next dev` 와 `next build` 는 **같은 `.next/` 를 쓴다.** 개발 서버가 떠 있는
디렉터리에서 프로덕션 빌드를 돌리면 개발 서버의 청크·매니페스트가 덮여 쓰이고,
브라우저가 `main-app.js` · `app-pages-internals.js` 를 **404** 로 받는다.

증상이 고약하다 — 페이지는 200 으로 그려지는데 **React 가 부팅되지 않는다.**
서버가 그린 초기 화면만 남아서, 클릭도 안 되고 `useEffect` 도 돌지 않는다.
"코드가 반영되지 않았다"거나 "권한 확인이 안 된다"처럼 보인다.
(2026-09-04 myjane 에서 실제로 겪었다. admin 콘솔이 계속 초기 상태로만 보였다)

대응 —

- 타입 확인은 **`npx tsc --noEmit`** 으로 한다. 빌드가 필요 없다
- 동작 확인은 **떠 있는 개발 서버에** 요청해서 한다
- 프로덕션 빌드가 꼭 필요하면 **개발 서버를 먼저 내린다**
- 이미 덮어썼으면 **개발 서버를 재시작**하면 복구된다

## 커밋 메시지
