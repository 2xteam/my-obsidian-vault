# 레퍼런스 사이트 분석 방법

참고할 사이트의 디자인을 우리 프로젝트로 옮길 때 쓰는 절차.
[[결쩜사 디자인 시스템]]·[[결쩜사 페이지 패턴]]이 이 방법으로 만들어졌다.

## 원칙: DOM만 보면 반드시 틀린다

처음 결쩜사를 분석할 때 CSS 변수와 DOM 구조만 읽고 문서를 만들었다.
색과 토큰은 맞았지만 **레이아웃과 인상은 완전히 빗나갔다.**

| DOM으로 본 것 | 실제 화면 |
|---|---|
| "섹션이 세로로 이어진다" | 옅은 배경 위에 **둥근 시트를 쌓는다** |
| 로그인 = 카드 하나 | **짙은 스토리 패널 + 흰 폼 카드 분할** |
| `font-family: Pretendard` (한 줄로 스침) | **서체가 인상의 절반.** 시스템 서체로 대체하면 다른 사이트가 된다 |
| 홈 섹션 3개 | JS로 렌더되는 섹션이 훨씬 많음 |

**반드시 브라우저에서 렌더링해 눈으로 본다.** DOM·CSS 조사는 그다음, 수치를 확인하는 용도다.

## 절차

### 1. 페이지 목록을 먼저 정한다

사이트맵이나 헤더 메뉴에서 전부 뽑는다. 하나도 빠뜨리지 않는다.
로그인·회원가입 같은 부수 화면이 오히려 우리가 만들 화면과 가장 닮아 있다.

### 2. 애니메이션을 끄고 캡처한다 ⭐

스크롤 등장 효과가 있는 사이트는 그냥 캡처하면 **빈 화면이 찍힌다.**
아래를 콘솔에서 실행한 뒤 캡처한다.

```js
// 등장 애니메이션 비활성화 + 숨겨진 요소 강제 표시
document.documentElement.classList.remove('motion-ready'); // 사이트마다 이름 다름
const st = document.createElement('style');
st.textContent =
  '*{animation:none!important;transition:none!important;' +
  'opacity:1!important;transform:none!important;' +
  'visibility:visible!important;clip-path:none!important}';
document.head.appendChild(st);
```

`motion-ready` 같은 스위치 클래스는 `document.documentElement.className` /
`document.body.className`을 찍어보면 찾을 수 있다.

### 3. 뷰포트를 페이지 높이만큼 늘려 한 장에 담는다

**스크롤하며 여러 장 찍지 말 것.** 스크롤 후에는 화면이 비어 나오는 경우가 잦다
(큰 filter·will-change 레이어가 있는 페이지에서 캡처가 래스터라이즈되지 않는다).

```
resize_window { width: 1100, height: 2400 }   // 페이지가 길면 3400까지
navigate → wait 2~3s → 위 스니펫 실행 → screenshot
```

페이지가 5000px를 넘으면 폭을 900으로 줄여 두 번에 나눠 찍는다.

### 4. 데스크톱과 모바일을 모두 본다

레이아웃이 완전히 바뀌는 경우가 많다.
결쩜사 로그인은 데스크톱에서 좌우 분할, 모바일에서는 위아래로 쌓인다.

```
resize_window { width: 1100, height: 2400 }   // 데스크톱
resize_window { preset: "mobile" }             // 375×812
```

### 5. 눈으로 본 것을 수치로 확인한다

캡처에서 구조를 파악한 뒤, 그 요소들의 실제 값을 뽑는다.

```js
// 텍스트로 요소를 찾아 계산된 스타일을 읽는다
const byText = t => [...document.querySelectorAll('*')]
  .filter(e => e.textContent.trim() === t && e.children.length === 0)[0];
const g = (e, ...p) => {
  if (!e) return null;
  const c = getComputedStyle(e);
  return { cls: e.className.toString().slice(0, 44),
           ...Object.fromEntries(p.map(k => [k, c[k]])) };
};

({
  btn:   g(document.querySelector('button[type=submit]'),
           'backgroundImage','borderRadius','padding','fontSize','fontWeight','boxShadow'),
  input: g(document.querySelector('input'),
           'borderRadius','border','padding','fontSize','backgroundColor'),
  title: g(byText('다시 만나요'), 'fontSize','fontWeight','letterSpacing','color'),
})
```

특히 챙길 값: **radius · 그림자 · padding · font-size/weight · letter-spacing · 그라디언트 각도**.
이 여섯 개가 "비슷한데 뭔가 다른" 느낌의 원인이다.

### 6. 색 체계를 통째로 가져온다

```js
// :root의 CSS 변수 전부
const vars = {};
for (const s of document.styleSheets) {
  try {
    for (const r of s.cssRules) {
      if (r.style && r.selectorText?.includes(':root')) {
        for (const p of r.style) if (p.startsWith('--')) vars[p] = r.style.getPropertyValue(p).trim();
      }
    }
  } catch {}
}
vars
```

CSS 변수가 없으면 화면에서 가장 많이 쓰인 색을 센다(요소를 순회하며 `color`·`backgroundColor` 빈도).

이미지(로고·아이콘)에서 색을 뽑을 때는 `sharp`로 픽셀을 읽는다.

```bash
node -e "const s=require('sharp');(async()=>{const{data,info}=await s('icon.png').ensureAlpha().raw().toBuffer({resolveWithObject:true});const c={};for(let i=0;i<data.length;i+=info.channels){const k='#'+[data[i],data[i+1],data[i+2]].map(v=>v.toString(16).padStart(2,'0')).join('');c[k]=(c[k]||0)+1}console.log(Object.entries(c).sort((a,b)=>b[1]-a[1]).slice(0,6))})()"
```

### 7. 서체를 확인한다

`getComputedStyle(document.body).fontFamily` — 여기서 끝내지 말고
**어떻게 불러오는지**(자체 호스팅인지 CDN인지)까지 확인해 같은 방법으로 적용한다.
서체를 시스템 스택으로 대체하면 나머지를 다 맞춰도 다른 사이트처럼 보인다.

### 8. 카피를 따로 수집한다

디자인만큼 문장이 인상을 만든다. 어미·줄바꿈·어휘를 그대로 옮겨 적어둔다.
`get_page_text`로 페이지 전문을 받아두면 편하다.

## 산출물 — 문서 3개로 나눈다

| 문서 | 담는 것 |
|---|---|
| **디자인 시스템** | 색·타이포·레이아웃·모션 토큰, 실측 수치, 파일 구성 |
| **페이지 패턴** | 페이지 골격, 히어로 변형, 반복 블록 목록, 페이지별 구조 |
| **카피 톤앤매너** | 어미, 문장 리듬, 브랜드 어휘, 제목 짓는 법 |

셋을 한 문서에 몰아넣으면 나중에 찾아 쓰기 어렵다.
각 문서 끝에 **"새 페이지 만들 때 체크리스트"**를 둔다.

## 함정 모음

- **스크롤 캡처 → 빈 화면**: 등장 애니메이션. 2번 스니펫으로 해결
- **스크롤 후 화면이 안 그려짐**: 뷰포트를 늘려 한 장으로 찍어 우회
- **첫 화면만 보고 판단**: 히어로는 페이지마다 다르고, 진짜 패턴은 본문 블록에 있다
- **DOM 섹션 수 ≠ 실제 섹션 수**: JS로 렌더되는 영역이 있다. 캡처가 진실이다
- **이미지 lazy 로딩**: 캡처 전에 2~3초 기다린다
- **한 페이지만 보고 일반화**: 최소 3개 페이지에서 반복되는 것만 "패턴"이라고 부른다
