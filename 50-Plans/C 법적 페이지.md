# C 법적 페이지

개인정보처리방침 · 이용약관 · 쿠키 설정. **포털(myjane)에 두고 여섯 앱 푸터에서 링크**한다.
회원과 세션을 공유하니 방침도 한 곳이어야 한다.

## ⚠️ 초안까지만이다

사용자가 "기본적인 내용으로 초안" 을 승인했다. 그 범위를 지킨다.

- **사실은 정확하게 쓴다** — 아래 실측한 수집 항목·위탁업체를 그대로 옮긴다.
  법적 문서에 실제와 다른 내용을 쓰면 초안이라도 위험하다
- **보관 기간·법적 근거 문구는 확정하지 않는다.** `(확인 필요)` 로 표시해 남긴다
- **법률 검토는 대신할 수 없다.** 공개 전에 사람이 봐야 한다

B 는 `app/legal/*` 을 건드리지 않았다 — C 것이라 손대지 않고 자리만 알려 둔다.

방침 문구에 반영할 것 —

- **필수 수집 항목은 이제 `name` · `email` · `password` 셋**이다.
  전화번호는 선택이고 "문자 알림을 받고 싶을 때만" 받는다
- `pendingEmail` 은 **아직 인증되지 않은 주소**다. 인증을 마치면 `email` 로 옮기고
  비운다. "수집 후 즉시 파기"가 아니라 **이동**이라는 점을 정확히 쓴다
- `emailToken` 은 30분 뒤 만료되고 **한 번 쓰면 폐기**한다. 보관 기간을 쓸 수 있는
  드문 항목이다 (`(확인 필요)` 가 아니어도 된다)
- `emailPromptSnoozedUntil` 은 "안내를 다시 띄울 시각" 하나뿐이다. 개인을 식별하는
  값이 아니지만 회원 문서에 있으니 표에는 넣는다
- 2026-09-07 에 **기존 이메일 계정 21건의 `emailVerified` 를 `true` 로 일괄 설정**했다.
  실제로 메일 인증을 거친 것이 아니라 **기존 사용자를 배려한 소급 처리**다.
  방침에 "이메일 인증 여부" 를 사실로 적을 때 이 점을 알고 있어야 한다

**앱 데이터는 각자 DB 에 있다** — `vocab` · `math` · `fit` · `hamhibokka`.
민감한 것은 FitLog 의 `fit` DB 다.

> ⚠️ **건강정보는 민감정보다.** FitLog 는 인바디 수치와 **피검사 결과**를 저장하고

| | 표에 적힌 것 | 실제 |

- 피검사 기록에는 수치 말고 **검사기관명·의뢰 병원명·접수번호**도 있다
  (`fitlog/models/BloodTest.ts` 의 `lab`)
- SMTP 기본값이 `smtp.gmail.com` 이다 (`lib/mail.ts`) — 발송처를 확정할 때 확인

## 쿠키

지금 쓰는 것은 **`snap_user` 하나**다 — 세션 쿠키, `.myjane.co.kr` 도메인 공유.
분석·광고 쿠키는 **없다.**

그래서 쿠키 배너는 필요 없을 가능성이 높다. 필수 쿠키만 쓰면 동의 대상이 아니다.
"쿠키 설정" 페이지는 **무엇을 쓰고 무엇을 안 쓰는지 밝히는 안내**로 만드는 것이
정직하다 — 껐다 켤 게 없는데 토글을 두면 거짓이 된다.

`localStorage` 도 쓴다 — 테마 선택(`fitlog_theme` 등). 쿠키가 아니지만 함께 밝힌다.

### 쿠키·로컬 저장소도 고쳤다 — 2026-09-07 재확인

- `snap_user` 는 **브라우저 세션 쿠키가 아니다.** `max-age=30일` 의 지속 쿠키다
  (`lib/session.ts` 의 `SESSION_TTL_SEC`). 안내에는 "유효기간 30일"로 적었다.
  필수 쿠키인 것은 그대로라 **동의 배너가 필요 없다는 결론은 바뀌지 않는다**
- 담기는 값도 적었다 — 회원 id · 이름 · 전화번호 · (이메일 · 닉네임 · userId) ·
  HMAC 서명 토큰 · 만료 시각. 평문 JSON 이다
- `localStorage` 에 **테마 말고 하나가 더 있다** — `typelog_guest`.
  로그인 없이 참여할 때 브라우저마다 만드는 UUID 로, 같은 질문지 재응시를 막는 데
  쓰고 **응답에 함께 저장된다** (`typelog/lib/guestKey.ts`). 안내에 넣었다
- `snap_user` 가 앱 사이 로그인 전달 과정에서 localStorage·sessionStorage 에
  잠깐 들렀다 지워진다. 이것도 밝혔다
- 분석·광고 코드는 **여섯 앱 어디에도 없다** — gtag · GA · Vercel Analytics ·
  픽셀류 0건. 검색해서 확인했다

## B 반영과 동의 기록 — 2026-09-07 (이어서 한 작업)

### B 의 수집 항목 변경을 방침에 반영했다

`app/legal/privacy/page.tsx` 의 표를 고쳤다.

- 계정을 **필수(이름·이메일·비밀번호)** 와 **선택(전화번호)** 두 줄로 갈랐다
- **이메일 인증** 줄을 새로 넣었다 — 인증 여부·토큰·만료·발송 시각·재안내 시각·대기 주소
- FitLog 의 키·성별·출생연도에 **선택**임을 밝혔다
- `emailVerified` 를 **2hbk 줄에서 뺐다** (이제 여섯 앱 공용)
- 표 아래에 "이메일 인증은 이렇게 다룹니다" 를 붙였다 —
  대기 주소는 인증 뒤 **옮기고** 비운다는 것, 토큰은 30분 만료·1회용이라는 것
- **소급 처리를 방침에 밝혔다.** 21건을 인증 없이 `true` 로 올린 것이라
  "그 계정의 인증 여부는 실제로 확인 메일을 주고받은 결과가 아닙니다" 라고 적었다.
  이걸 안 적으면 방침이 사실과 다르다

### 메일 발송처를 확정했다

사용자 확인 — **Gmail(Google) SMTP** 를 쓰고 있다. 위탁업체 표에
`Google (Gmail SMTP)` 로 적고 `(확인 필요)` 를 뗐다.
⚠️ **발송 계정 주소는 방침에도 볼트에도 쓰지 않았다.** 공개되는 문서다.

### 동의 — 화면·라우트·스키마 셋 다 했다

사용자가 "스키마까지" 를 골랐다. 화면만 막으면 API 를 직접 부르는 쪽이 통과한다.

```
app/signup/page.tsx              체크박스 2개(둘 다 필수) + 제출 차단 + 값 전송
app/api/auth/register/route.ts   agreeTerms·agreePrivacy 검증 → 없으면 400
여섯 앱 models/User.ts           termsAgreedAt · privacyAgreedAt · agreedPolicyVersion
lib/legalVersion.ts              POLICY_VERSION — 개정일의 원본은 이 파일 하나
```

- 체크박스는 `globals.css` 에 클래스를 만들지 않고 **선언된 토큰을 쓰는 인라인
  스타일**로 했다 (A 가 그 파일을 고치는 중이다). `<Mark required />` 를 재사용해
  "필수" 를 글자로 적는다 — 색만으로 구분하지 않는다
- 쿠키는 **동의 대상이 아니라** 체크박스를 두지 않고 안내 링크만 걸었다.
  필수 쿠키 하나뿐이라 토글을 두면 거짓이 되는 것과 같은 이유다
- `POLICY_VERSION` 을 따로 둔 이유 — 세 페이지의 "최종 개정일" 과 DB 에 남는
  동의 버전이 **같은 값이어야** 나중에 재동의 대상을 골라낼 수 있다.
  따로 적어 두면 한쪽만 바뀐다

⚠️ **`useCallback` 의존성 배열에 동의 상태를 빼먹으면 영영 제출이 안 된다.**
`submit` 이 초기값 `false` 를 물고 있어서 체크를 해도 막힌다. 실제로 그렇게
써 놓고 브라우저에서 잡았다. deps 에 `agreeTerms`·`agreePrivacy` 를 넣어야 한다.

⚠️ **기존 회원은 동의 필드가 비어 있다.** 없다고 로그인을 막으면 안 된다 —
`email` 을 required 로 걸면 안 되는 것과 같은 이유다. 스키마 주석에 적어 뒀다.

라우트를 실제로 찔러 확인했다 (3010).

```
동의 없음        400 "이용약관과 개인정보 수집·이용에 동의해 주세요."
동의 false       400 같은 메시지
동의 true+잘못된 전화번호  400 "전화번호 형식이 올바르지 않습니다"  ← 동의는 통과했다
```

### 다섯 앱 랜딩 푸터는 A 커밋에 딸려 들어갔다

`app/page.tsx` 에 넣은 링크가 커밋되지 않은 채로 있었는데, A 세션이

내용은 맞아서 그대로 뒀다. **같은 저장소에서 병행할 때 실제로 일어나는 일이다** —
스테이지할 때 파일을 골라야 하는 이유.

아동에게서 직접 연락처를 받지 않으니 법정대리인 동의 문제가 깔끔해진다.

만드는 것은 별개의 일이고 **B 와 겹친다** — `users` 컬렉션에 부모-자녀 관계와

### ⚠️ 탈퇴 기능이 2hbk 에만 있다 — 2026-09-07 확인

`2hbk/app/api/me/route.ts` 의 `DELETE` 하나뿐이다. myjane · fitlog · SnapWord ·
SnapNote · typelog 에는 **탈퇴 경로가 없다.**

그 2hbk 탈퇴도 정한 정책과 다르다.

- **즉시 삭제한다** — 목표·참가·팔로우·초대를 바로 지운다. "일정 기간 보관" 이 아니다
- PIN 이 있는 계정(다른 앱을 쓰는 계정)은 2hbk 필드만 null 로 비우고 계정은 남긴다
- **R2 이미지는 안 지운다** — 프로필·목표 이미지 파일이 그대로 남는다

그래서 약관 초안에 "이용자는 언제든지 탈퇴할 수 있습니다" 라고 쓸 수 없었다.
지금 사실대로 "직접 탈퇴할 수 있는 곳은 2hbk 뿐이고 나머지는 연락처로 요청" 이라고
적고 `(확인 필요)` 를 달아 뒀다. **공통 탈퇴를 만들면 그 문구를 고친다.**
