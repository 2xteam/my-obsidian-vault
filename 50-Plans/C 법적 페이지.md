# C 법적 페이지

개인정보처리방침 · 이용약관 · 쿠키 설정. **포털(myjane)에 두고 여섯 앱 푸터에서 링크**한다.
회원과 세션을 공유하니 방침도 한 곳이어야 한다.

## ⚠️ 초안까지만이다

사용자가 "기본적인 내용으로 초안" 을 승인했다. 그 범위를 지킨다.

- **사실은 정확하게 쓴다** — 아래 실측한 수집 항목·위탁업체를 그대로 옮긴다.
  법적 문서에 실제와 다른 내용을 쓰면 초안이라도 위험하다
- **보관 기간·법적 근거 문구는 확정하지 않는다.** `(확인 필요)` 로 표시해 남긴다
- **법률 검토는 대신할 수 없다.** 공개 전에 사람이 봐야 한다

### 위 표를 고쳤다 — 2026-09-07 재확인

초안을 쓰면서 코드를 다시 봤더니 위 표가 **두 군데 좁았다.** 방침에는 고친 값을 썼다.

| | 표에 적힌 것 | 실제 |
|---|---|---|
| **OpenAI** | 결과지 이미지 · 채팅 | **SnapWord 단어장 사진**(`api/openai-vision`)과 **SnapNote 오답노트 사진**(`lib/wrongNoteVision.ts`)도 나간다. FitLog 만이 아니다 |
| **R2** | 결과지 · 프로필 이미지 | **SnapNote 오답노트 사진**도 올라간다 (`SnapNote/lib/r2.ts`) |

또 두 가지를 덧붙였다.

- FitLog **AI 상담**은 대화만 보내는 게 아니라 **저장된 인바디·피검사 수치를 지침에
  실어** 보낸다 (`lib/chatOpenAi.ts` 의 「사용자 기록」 블록). 건강정보가 이미지
  경로가 아니라 **대화 경로로도** 나간다는 뜻이다
- 대화는 OpenAI **Conversations 에 남는다** (`ChatThread.openAiConversationId`)
- 피검사 기록에는 수치 말고 **검사기관명·의뢰 병원명·접수번호**도 있다
  (`fitlog/models/BloodTest.ts` 의 `lab`)
- SMTP 기본값이 `smtp.gmail.com` 이다 (`lib/mail.ts`) — 발송처를 확정할 때 확인

## 쿠키

지금 쓰는 것은 **`snap_user` 하나**다 — 세션 쿠키, `.myjane.co.kr` 도메인 공유.
분석·광고 쿠키는 **없다.**

그래서 쿠키 배너는 필요 없을 가능성이 높다. 필수 쿠키만 쓰면 동의 대상이 아니다.
"쿠키 설정" 페이지는 **무엇을 쓰고 무엇을 안 쓰는지 밝히는 안내**로 만드는 것이
정직하다 — 껐다 켤 게 없는데 토글을 두면 거짓이 된다.

`localStorage` 도 쓴다 — 테마 선택(`fitlog_theme` 등). 쿠키가 아니지만 함께 밝힌다.

### 쿠키·로컬 저장소도 고쳤다 — 2026-09-07 재확인

- `snap_user` 는 **브라우저 세션 쿠키가 아니다.** `max-age=30일` 의 지속 쿠키다
  (`lib/session.ts` 의 `SESSION_TTL_SEC`). 안내에는 "유효기간 30일"로 적었다.
  필수 쿠키인 것은 그대로라 **동의 배너가 필요 없다는 결론은 바뀌지 않는다**
- 담기는 값도 적었다 — 회원 id · 이름 · 전화번호 · (이메일 · 닉네임 · userId) ·
  HMAC 서명 토큰 · 만료 시각. 평문 JSON 이다
- `localStorage` 에 **테마 말고 하나가 더 있다** — `typelog_guest`.
  로그인 없이 참여할 때 브라우저마다 만드는 UUID 로, 같은 질문지 재응시를 막는 데
  쓰고 **응답에 함께 저장된다** (`typelog/lib/guestKey.ts`). 안내에 넣었다
- `snap_user` 가 앱 사이 로그인 전달 과정에서 localStorage·sessionStorage 에
  잠깐 들렀다 지워진다. 이것도 밝혔다
- 분석·광고 코드는 **여섯 앱 어디에도 없다** — gtag · GA · Vercel Analytics ·
  픽셀류 0건. 검색해서 확인했다

### 푸터 — 앱마다 **두 개**다

`components/SiteFooter.tsx` 는 `app/(app)/layout.tsx` 에서만 쓴다. **로그인한 뒤의
화면이다.** 각 앱의 소개 페이지(`app/page.tsx`)에는 어두운 푸터가 따로 박혀 있다.
가입 전 방문자가 방침을 찾는 자리가 그쪽이라 **둘 다** 고쳤다.

```

다섯 앱 app/page.tsx 의 <footer>    소개 페이지 — --on-dark-dim 링크 3개
```

⚠️ **myjane 은 아직 안 했다.** myjane 의 푸터는 `app/page.tsx` 안에 있고
그 파일은 A 가 작업 중이다 (`<ScrollProgress />` · `app/elements.css` 가 들어와 있다).
`.site-footer-legal` 규칙은 `globals.css` 에 미리 넣어 뒀으니, A 가 끝나면
푸터에 링크 세 개만 넣으면 된다.

### 만 14세 미만 — 정해진 방향

보호자가 가입하고, 그 계정 안에서 **자녀를 추가**한다. 로그인은 보호자 계정 하나로
하고 (본인 / 자녀1 / 자녀2 … 를 골라 들어간다), 자녀의 데이터는 부모 계정을 물고
**별도 row 로** 생성한다. 자녀끼리·부모자녀는 **자동으로 친구 맺음** 상태로 만든다.

아동에게서 직접 연락처를 받지 않으니 법정대리인 동의 문제가 깔끔해진다.

⚠️ **아직 만들지 않았다.** 방침에는 "이 방식은 아직 만들어지지 않았습니다,
준비되기 전까지 만 14세 미만 가입을 권하지 않습니다" 라고 적어 뒀다.
만드는 것은 별개의 일이고 **B 와 겹친다** — `users` 컬렉션에 부모-자녀 관계와
프로필 구분이 들어가야 하고, 로그인 화면에 프로필 고르기가 붙는다.
2hbk 의 `Follow` 자동 생성도 함께 봐야 한다.

### ⚠️ 탈퇴 기능이 2hbk 에만 있다 — 2026-09-07 확인

`2hbk/app/api/me/route.ts` 의 `DELETE` 하나뿐이다. myjane · fitlog · SnapWord ·
SnapNote · typelog 에는 **탈퇴 경로가 없다.**

그 2hbk 탈퇴도 정한 정책과 다르다.

- **즉시 삭제한다** — 목표·참가·팔로우·초대를 바로 지운다. "일정 기간 보관" 이 아니다
- PIN 이 있는 계정(다른 앱을 쓰는 계정)은 2hbk 필드만 null 로 비우고 계정은 남긴다
- **R2 이미지는 안 지운다** — 프로필·목표 이미지 파일이 그대로 남는다

그래서 약관 초안에 "이용자는 언제든지 탈퇴할 수 있습니다" 라고 쓸 수 없었다.
지금 사실대로 "직접 탈퇴할 수 있는 곳은 2hbk 뿐이고 나머지는 연락처로 요청" 이라고
적고 `(확인 필요)` 를 달아 뒀다. **공통 탈퇴를 만들면 그 문구를 고친다.**
