# Plans MOC

**여러 세션이 나눠 진행하는 작업의 계획서**를 둔다.
한 세션이 다 하기엔 큰 일을, 다른 세션이 이어받거나 병행할 수 있게 적어 둔 것이다.

계획서는 실행 중에도 고친다 — 진행하다 알게 된 것을 여기 반영하고,
끝나면 결론을 해당 패턴/디자인 노트로 옮긴 뒤 이 계획서에 "완료"를 적는다.

## 진행 중 — 2026-09-07 착수

결쩜사 사이트를 다시 보고 가져올 것을 세 덩어리로 나눴다.
성격이 달라서 **병행할 수 있다.**

| | 계획서 | 성격 | 상태 |
|---|---|---|---|
| **A** | [[A 디자인 요소 추가]] | CSS·작은 컴포넌트. myjane 에서 먼저 검증 | 착수 |
| **B** | [[B 로그인·회원가입 개편]] | 인증 흐름 + 공유 `user` DB | **구현 완료** — 실제 메일 발송만 미확인 |
| **C** | [[C 법적 페이지]] | 개인정보처리방침·이용약관·쿠키. 초안 | 초안 · **B 의 수집 항목 변경 반영 필요** |

**A 를 먼저 하는 이유** — B 의 회원가입 화면을 고칠 때 A 의 요소(프로그레스 바,
밑줄 포인트, 프로세스 타임라인, 카드 포인트)가 이미 있으면 그 작업이 쉬워진다.

### 세션이 나눠 잡을 때

- **A** 는 myjane 만 만진다. 검증 후 다섯 앱으로 옮긴다
- **B** 는 여섯 앱의 인증 경로와 `user` DB 를 건드린다. A·C 와 파일이 겹치지 않는다
- **C** 는 새 페이지와 푸터 링크만 추가한다. 겹치는 파일은 푸터뿐이다

### B → C 로 넘어간 것 (2026-09-07)

B 가 끝나면서 C 에 두 가지가 넘어갔다. [[C 법적 페이지]] 에 자리와 방법을 적어 뒀다.

1. **가입 화면의 동의 체크박스** — B 가 `myjane/app/signup/page.tsx` 에 주석으로
   자리만 비워 두었다. 문구·링크가 C 의 결과물이라 먼저 만들면 두 벌이 된다
2. **수집 항목이 바뀌었다** — 이메일이 필수가 되고 전화번호가 선택이 됐다.
   이메일 인증 필드 6개가 새로 생겼고 `emailVerified` 가 2hbk 전용에서 공용이 됐다.
   **방침 본문에 옛 내용이 들어갔다면 고쳐야 한다**
