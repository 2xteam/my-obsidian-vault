# 여섯 앱 디자인 시스템

**어느 앱을 만지든 이 노트를 먼저 읽는다.** [[결쩜사 디자인 시스템]]과 [[결쩜사 페이지 패턴]]은
*레퍼런스 사이트를 기술한* 노트다. 이 노트는 **우리 여섯 앱이 실제로 지키는 것**이다.
둘이 갈리는 지점을 아래 "결쩜사와 갈라진 곳"에 모았다.

## 가장 먼저 — 검사부터 돌린다

```bash
cd C:/Dev/myjane && npm run design:check
```

글로만 적어둔 규칙은 세션마다 놓친다. 실제로 그래서 이런 일이 있었다.

- myjane 만 원형 장식을 걷고 **다섯 앱에 그대로 남아** 인상이 갈렸다 (2026-09-07 해소)
- 금색을 글자로 쓴 자리가 5곳 (흰 시트 위 2.01:1)
- 강조색 배경에 순수 검정을 얹은 자리가 24곳 (3.01:1)
- 선언 없이 쓰이는 CSS 변수 19개 — 그 화면들은 카드 배경이 통째로 빠진 채 렌더됐다

검사기는 `myjane/scripts/design-check.mjs` 다. 규칙 A~F 와 **기준선**을 들고 있다.
기준선은 "아직 못 고쳤지만 늘어나면 실패"라는 뜻이다 — 0으로 만들 수 없다고
규칙을 지우면 다시 스며든다. `--all` 로 기준선 항목을 펼쳐 본다.

## 결쩜사와 갈라진 곳

| 결쩜사 | 우리 | 왜 |
|---|---|---|
| 실(結) 곡선 장식 (타원 호 + 금색 점) | **쓰지 않는다** | 밝은 바탕에서 얇은 선이 얼룩처럼 보인다 |
| 보라 `#7C3AED` | 먹청 `#116271` | 색까지 같아서 너무 닮았다 → [[먹청 톤 팔레트]] |
| 라이트 전용 | fitlog·2hbk 는 다크·커스텀도 | 사용자가 고를 수 있게 |

**가져온 것은 그대로 쓴다** — 시트 쌓기, `eyebrow → headline → lead` 순서,
짙은 시트로 히어로를 잡고 어두운 푸터로 닫기, 금색은 강조점에만,
헤드라인 명조(Gowun Batang 700), 순수 검정·회색을 쓰지 않는 원칙.

### 원형 장식 — 되살리지 말 것

2026-09-07 에 여섯 앱에서 걷었다. 걷어낸 것은 셋이다.

```
components/Sheet.tsx   Ornament 함수 · ornament prop · 타입 · 렌더 조각
app/globals.css        .sheet-ornament 규칙
호출부                  ornament 속성 (앱마다 1~12곳)
```

⚠️ **`<circle>` 이 들어간 SVG 를 일괄로 훑으면 안 된다.** 내용인 SVG 가 있다 —
FloatingChat·home 의 스마일리, fitlog `BodyRadar` 의 레이더 차트,
SnapWord `BouncingSmiley` 의 무지개색 배열.
장식만 정확히 집는다: `.sheet-ornament` 규칙과 `ornament` prop.

`radial-gradient(circle at …)` 는 **남긴다.** 이름에 circle 이 붙어 있어도
테두리 없는 확산 글로우이고, 짙은 시트의 빛이 이쪽이다.

prop 을 no-op 으로 남기지 말고 타입에서 없앤다 — 빠진 호출부를 `tsc --noEmit` 이 잡는다.

## 루트(소개) 페이지 헤더·푸터

다섯 앱이 같은 골격을 쓴다. 기준은 **fitlog** 다.

```tsx
<div style={{ minHeight: "100vh", background: "var(--bg-primary)" }}>
  <header style={headerStyle}>            // sticky · top 0 · z 40 · borderBottom
    <div className="page" style={{ ...headerInner, paddingTop: 14, paddingBottom: 14 }}>
      <span className="row" style={{ gap: 9 }}>
        <AppIcon size={30} priority />
        <span style={{ fontWeight: 900, letterSpacing: "-0.02em" }}>앱이름</span>
      </span>
      <LandingHeaderAuth />
    </div>
  </header>
  <main className="page">…</main>
  <footer style={footerStyle}>            // --footer-bg · --on-dark
    앱이름 · myjane 워드마크 · @2026 myjane All rights reserved
  </footer>
</div>
```

- 아이콘은 **`AppIcon` 컴포넌트**를 쓴다. 생 `<img src="/site-title-icon.png">` 를 쓰지 말 것
  (2hbk 가 그랬다). 컴포넌트는 기본 `alt` 만 앱마다 다르다
- 푸터 색은 토큰이다 — `--footer-bg` · `--on-dark` · `--on-dark-faint`.
  다섯 앱이 `#061a1f` · `#fff` · `rgba(230,244,246,0.62)` 를 박아 쓰고 있었다
- `LandingHeaderAuth` 는 로그인 상태에 따라 "내 기록" / "로그인" 으로 갈린다.
  상태가 정해지기 전에는 자리만 잡는다 → [[인증과 세션 공유]]
- TypeLog 은 `LandingCta` 가 없다. **로그인 없이도 해볼 수 있어서** 본문 CTA 가
  "타입 찾아보기"이고 세션에 따라 갈리지 않는다

### ⚠️ 폰트는 링크가 없으면 조용히 떨어진다

2026-09-07 에 사용자가 "글자체가 약간 달라 보인다"고 했다. 원인이 이것이었다.

  SnapWord · SnapNote   body 스택에 Pretendard 가 없음 → 시스템 기본
                        layout.tsx 에 폰트 링크 0건 → Gowun Batang 이 일반 명조로

`.headline` 은 다섯 앱 모두 `"Gowun Batang", serif` 를 요구한다.
**링크가 없어도 오류나 경고가 나지 않는다** — serif 로 조용히 대체된다.

`app/layout.tsx` 의 `<head>` 에 네 줄이 있어야 한다.

```
preconnect fonts.googleapis.com
preconnect fonts.gstatic.com (crossOrigin)
Gowun+Batang:wght@400;700
pretendard-dynamic-subset.min.css (jsdelivr)
```

body 스택: `Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", Roboto, sans-serif`

새 앱을 만들 때 이 네 줄을 빼먹으면 **다른 앱과 미묘하게 달라 보인다.**

## 색 — 원본은 한 곳이다

```
myjane/design/palette.json        ← 여기만 고친다
myjane 에서 npm run palette -- --write
→ 여섯 앱의 app/palette.css 가 다시 만들어진다 (생성 파일)
```

각 앱 `globals.css` 는 `@import "./palette.css"` 한 줄만 두고 색 선언이 없다.
쓰기 전에 대비 31건을 검사하고 **하나라도 미달이면 아무 파일도 쓰지 않는다.**
자세한 것은 → [[먹청 톤 팔레트]]

### 면적용과 글자용은 다른 토큰이다

이 팔레트에서 같은 문제를 **세 번** 겪었다.

| 면적 | 글자 | 왜 |
|---|---|---|
| `--accent` | `--accent-ink` | 살구를 썼을 때 2.37:1 |
| `--point` `--gold` | `--point-ink` | 금색 알약 위 금색 글자 2.01:1 |
| `--danger` `--success` | `--danger-ink` `--success-ink` | 흰 카드 위 4.05 / 3.35 |

먹청은 어두워서 `--accent` = `--accent-ink` 지만 **토큰은 따로 둔다.**
다음에 밝은 색을 고르면 그때 값만 갈라진다.

### 리터럴로 쓰지 않는 면들

지난 두 번의 색 교체에서 손이 가장 많이 간 자리다. 토큰이 있다.

```
--sheet-dark  --sheet-dark-glow  --footer-bg  --btn-gradient  --btn-shadow
--on-dark  --on-dark-dim  --on-dark-faint  --border-on-dark
--accent-on-dark  --gold-on-dark  --shadow-rgb
```

`--shadow-rgb` 는 `rgba(var(--shadow-rgb), 0.1)` 처럼 쓴다.

## 공통 컴포넌트

`components/Sheet.tsx` 는 다섯 앱에 **같은 파일이 복사돼 있다** (myjane 은 순수 마크업).

```tsx
<Sheet tone="plain|tint|dark|gold" eyebrow="STUDY · 공부 기록"
       headline={…} lead={…} center>
```

⚠️ 복사본이라 **한 앱만 고치면 갈라진다.** Sheet 를 바꿀 때는 다섯 앱을 함께 바꾸고,
바꾼 내용을 이 노트에 적는다. 색과 달리 컴포넌트는 아직 생성 장치가 없다 —
아래 "다음에 만들 것" 참고.

시트 배경은 **번갈아** 쓴다(`.sheet` / `.sheet--tint`). 순서를 바꿀 때
`sheet--tint` 가 연속되지 않는지 확인한다.

## 아이콘

여섯 개가 같은 기하학(짙은 타일 + 게이지 호)을 공유한다.
**하나만 바꾸면 가족이 어긋난다** — 항상 여섯 개를 함께 바꾸고, PNG 파생물 56개를
다시 만든다 → [[앱 공통 UI와 아이콘]]

## 검사 규칙 A~F

| | 규칙 | 왜 |
|---|---|---|
| A | 원형 장식 잔재 (`sheet-ornament` · `ornament`) | 위 참고 |
| B | 선언 없이 쓰이는 CSS 변수 | 선언이 없으면 그 속성이 통째로 빠진 채 렌더된다 |
| C | 면적용 색을 글자로 (`color: var(--point)` 등) | `-ink` 토큰을 쓴다 |
| D | 순수 검정·흰색을 글자색으로 | `--on-accent` (강조색 위) · `--on-dark` (짙은 면 위) |
| E | 토큰을 리터럴로 선언 (`globals.css` 안의 hex) | 원본은 `palette.json` 하나 |
| F | 폰트 링크 누락 | 링크가 없으면 **조용히** 일반 명조·시스템 폰트로 떨어진다 |

### 현재 기준선 (2026-09-07)

- **C 46건** — `--danger` 를 오류 문구에 쓰는 자리. `--danger-ink` 로 바꾸면 색이 조금
  어두워지고(`#e0455f → #a83447`), `--success` 는 색상까지 130°로 밀어야 해서
  개선 표시의 외형이 바뀐다. **사용자 확인이 필요하다.**
- **D 14건** — `#fff` 이 세 종류로 섞여 있다: 강조색 배경 위, 짙은 면 위,
  그리고 푸터처럼 배경까지 리터럴인 자리. 자리마다 달라 일괄 치환이 안 된다.
  (랜딩 푸터를 토큰으로 바꿔 18 → 14 로 줄었다)

A · B · E · F 는 0건이다. **이 넷이 걸리면 새로 생긴 것이니 바로 고친다.**

## 예외로 빼둔 자리

검사기의 `ALLOW` 에 이유와 함께 적혀 있다. 새로 추가할 때는 **왜 예외인지** 함께 쓴다.

- `BouncingSmiley.tsx` · 단어 상세 — 튀는 스마일리용 무지개색 배열
- `ThemeProvider.tsx` — 커스텀 테마 기본값(사용자가 고르는 값)
- `api/auth/*` — 이메일 HTML. **CSS 변수를 못 쓴다.** 리터럴이 남을 수밖에 없는 유일한 자리
- `opengraph-image` — 런타임 CSS 가 없다
- `palette.css` — 생성 파일
- `admin.css` — 포털 admin. 팔레트 별칭을 쓰는 별도 화면
