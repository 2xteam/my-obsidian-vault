# 먹청 톤 팔레트

**여섯 앱(myjane · SnapWord · SnapNote · fitlog · 2hbk · typelog)이 함께 쓰는 색**이다.
원본은 `myjane/design/palette.json` 하나뿐이다 → 아래 [[#⭐ 색은 이제 한 곳에서 바꾼다]] [[결쩜사 디자인 시스템]]의 **구조를 그대로 쓰고 색만 갈았다** —
시트 쌓기, 아이브로우 → 헤드라인 → 본문, **짙은 시트로 히어로를 잡고 어두운 푸터로
닫기**, 금색 포인트까지. 페이지 구성은 [[결쩜사 페이지 패턴]]을 따른다.

## 색 토큰

```css
--bg:            #f7fbfb;   /* 옅은 청백 */
--surface:       #ffffff;   /* 시트 — 순수 흰색 */
--surface-hover: #e8f2f3;   /* 옅은 청록 시트(tint) */
--border:        rgba(17, 98, 113, 0.14);
--border-strong: rgba(17, 98, 113, 0.42);
--text:          #0f2027;
--text-dim:      #566b70;

--accent:      #116271;     /* 면적·글자·테두리 모두 */
--accent-ink:  #116271;     /* 같은 값 — 아래 참고 */
--accent-soft: rgba(17, 98, 113, 0.08);
--on-accent:   #ffffff;
--placeholder: #5e7377;

--gold-from: #1a7f8f;       /* 헤드라인 그라디언트 */
--gold-to:   #116271;
--gold:      #c9a84c;       /* 좁은 면적만 */

먹청 버튼:   linear-gradient(135deg, #14788a, #0d5866)
짙은 시트:   linear-gradient(150deg, #071c22, #0e3037 65%, #134450)
어두운 푸터: #061a1f
짙은 면 글자: #eef7f8 / rgba(230, 244, 246, 0.74)
짙은 면 금색: #ead58c
짙은 면 먹청: #5fb8c9
그림자:      rgba(6, 34, 40, α)

의미색 (여섯 앱 공통)
--danger:  #e0455f  면적    --danger-ink:  #a83447  글자
--success: #2f9e74  면적    --success-ink: #2f7d3f  글자
```

⚠️ 위 값을 여기서 읽고 코드에 적어 넣지 말 것. **원본은 `palette.json`** 이고
이 표는 설명용이다. 값이 갈리면 원본이 맞다.

## 강조색이 한 단계다 — 그게 이 색을 고른 값어치다

| 조합 | 대비 |
|---|---|
| 먹청 `#116271` on 바탕 | 6.69 |
| 먹청 on 흰 시트 | 6.98 |
| 흰 글자 on 먹청 | 6.98 |
| `--text` `#0f2027` on 흰 시트 | 16.72 |
| `--text-dim` `#566b70` on 흰 시트 | 5.63 |
| 금 `#c9a84c` on 흰 시트 | **2.29** ← 글자로 못 쓴다 |

먹청은 어두워서 **면적·글자·테두리에 같은 값을 쓸 수 있다.**
그래서 `--accent` = `--accent-ink` 이고 `--on-accent` 는 흰색이다.
결쩜사의 보라(`#7c3aed`, 5.70)와 같은 성질이다.

**금색만 예외다.** 흰 시트 위 2.29:1 이라 글자로 쓰면 안 된다.
배지 배경·구분선 같은 좁은 면적, 그리고 짙은 면(8.90:1)에만.

## ⚠️ 밝은 강조색을 고르면 대가를 치른다

이 자리에 한 번 **살구 `#FF805D`** 를 넣었다가 되돌렸다. 기록으로 남긴다.

밝은 강조색은 크림 위 2.30:1, 흰 글자로 2.47:1 로 **글자에 못 쓴다.**
큰 글자 기준(3:1)에도 미달이다. 그래서 이런 것들이 필요했다.

- 글자용 진한 값을 따로 두기 (`--accent-ink` 분리)
- 버튼 위 글자를 흰색이 아니라 먹으로 (`--on-accent`)
- 면이 어두워지는 자리마다 글자색을 또 따로 잡기

레퍼런스로 삼았던 네이버 예약 프로모션 페이지도 코랄 알약에 흰 글자(2.47),
코랄 카드에 노란 글자(2.11)를 쓴다. **저쪽도 기준 미달인데, "STEP 01" 처럼
읽지 않아도 되는 장식 라벨이라 넘어가는 것이다.**
한 번 보고 지나가는 광고와 매일 수치를 읽는 앱은 다르다.

색값을 실측해서 가져오는 건 좋다. **글자색 규칙까지 가져오면 안 된다.**

## 밝은 면에 어두운 면이 필요하다

살구를 쓰던 동안 결쩜사의 짙은 히어로·어두운 푸터를 뺐다가 되돌렸다.
빼면 페이지가 평평해지고, 넣으면 무거워 보였다 — 사실 문제는 어두운 면이 아니라
**강조색이 밝아서 대조를 만들 수단이 없던 것**이었다.

먹청에서는 짙은 시트가 강조색과 같은 계열이라 어색하지 않다.
흰 시트와 바탕은 1.04:1 로 색으로는 안 갈리고, **분리는 그림자가 한다** —
결쩜사 원본도 같은 방식이다.

## 아이콘 — 밝은 페이지라도 아이콘은 짙어야 한다

여섯 개(myjane + 다섯 앱)가 같은 기하학을 공유한다 → [[앱 공통 UI와 아이콘]]
하나만 바꾸면 가족이 어긋나므로 항상 함께 바꾼다.

```
타일     #134450 → #071c22
트랙 호  #4a95a6
심볼     #eef7f8
금색     #e8d18a · #ead58c  (그대로)
```

32px 파비콘까지 내려가고 획이 11이다.

| 후보 | 결과 |
|---|---|
| 밝은 강조색 타일 | 금색 호가 **1.69:1** — 사라진다 |
| 크림·청백 타일 | 시트가 흰색이라 **1.07:1** — 테두리가 사라진다 |
| 짙은 타일 | 심볼 12.33 · 금색 8.90 — 전부 살아난다 |

**페이지에서 어두운 면을 쓰는 것과 아이콘이 짙은 것은 다른 문제다.**
전자는 화면 전체의 인상이고, 후자는 작은 물체의 판독성이다.

### ⚠️ 색이 rgba 로 박혀 있었다

SnapWord·SnapNote·fitlog 는 트랙 호를 `rgba(200,184,255,.32)` 로 썼다.
헥스만 훑는 표가 이 셋을 놓쳐 **아이콘 세 개만 옛 색으로 남았다.**
여섯 개를 한 장에 나란히 렌더해 보고서야 눈에 띘다.

지금은 여섯 개 모두 **solid `#4a95a6` 으로 통일**했다.
앱마다 색 처리 방식이 다른 것 자체가 함정이었다.
그래도 색 교체는 hex · rgba · 축약형(`#fff`)을 모두 훑고, 끝나면 여섯 개를 모아 본다.

### PNG 파생물은 56개다

각 앱이 서로의 링크 아이콘을 갖고 있다. 파일 이름과 **현재 픽셀 크기를 그대로
유지**하며 다시 만든다 — 앱마다 favicon 이 32인 곳과 192인 곳이 섞여 있다.
typelog 의 16px 은 단순화한 `app-icon-16.svg` 를 쓴다.

## 원형 장식은 걷어냈다

`.sheet-ornament`(타원 두 개 + 금색 점)와 `.auth-story` 의 호 세 개를 없앴다.
실(結) 모티프였지만 사용자가 얼룩처럼 보인다고 했다.
`radial-gradient(circle at …)` 는 남긴다 — 이름에 circle 이 붙어 있어도
테두리 없는 확산 글로우다.

## 대비 검사 자동화

7개 페이지를 헤드리스 크롬에 **CDP 로 붙여** 실제 렌더 상태에서 잰다.
Node 22+ 의 전역 `WebSocket` 을 쓰면 의존성이 필요 없다.

이 검사가 **팔레트 규칙을 문서에 쓰고 나서도 코드에서 어긴 자리**를 네 번 찾았다 —
워드마크, 입력칸 포커스 테두리, 복구 페이지 링크, placeholder.

### ⚠️ 도구가 틀리면 오탐이 쏟아진다

두 번 물렸다.

**① gradient 의 어느 끝이 최악인가.** 처음엔 늘 "가장 어두운 끝"을 썼다.
어두운 면에 얹은 **밝은 글자는 그라디언트의 밝은 쪽에서** 대비가 낮아진다.
한쪽만 보면 정상인 화면에서 미달이 쏟아진다. 양 끝을 적어두고 **불리한 쪽**을 쓴다.

**② 표가 낡으면 조용히 틀린다.** 팔레트를 갈았는데 그라디언트 표를 안 고쳐서
미달 9건이 나왔다. 전부 오탐이었다. 색을 바꿀 때 도구도 같이 고친다.

### ⚠️ Git Bash 가 경로를 바꾼다

`/login` 같은 인자를 윈도우 경로로 바꿔버린다 (`C:/Program Files/Git/login`).
그러면 **아무것도 재지 않고 "미달 0건"** 이 나온다 — 거짓 통과다.
`MSYS_NO_PATHCONV=1` 을 붙이고, **검사한 글자 수를 꼭 함께 출력**해 0이 아닌지 본다.

## ⭐ 색은 이제 한 곳에서 바꾼다

245곳을 손으로 바꾼 뒤에 만들었다. 다음부터는 이렇게 한다.

```
myjane/design/palette.json        ← 원본. 여기만 고친다
myjane 에서 npm run palette -- --write
→ 여섯 앱의 app/palette.css 가 다시 만들어진다
```

`app/palette.css` 는 **생성 파일**이다. 직접 고치면 다음 실행에서 덮어쓴다.
각 앱 `globals.css` 는 `@import "./palette.css"` 한 줄만 두고 색 선언이 없다.

myjane 과 다섯 앱이 같은 역할에 다른 이름을 쓴다(`--bg` vs `--bg-primary`).
역할 → 이름 표는 `scripts/sync-palette.mjs` 가 들고 있다. 새 앱은 다섯 앱 쪽 이름을 쓸 것.

### 리터럴이었던 면들도 토큰이 됐다

지난 두 번의 색 교체에서 손이 가장 많이 간 자리가 정확히 여기였다.

```
--sheet-dark  --sheet-dark-glow  --footer-bg  --btn-gradient  --btn-shadow
--on-dark  --on-dark-dim  --on-dark-faint  --border-on-dark
--accent-on-dark  --gold-on-dark  --shadow-rgb
```

**리터럴로 다시 쓰지 말 것.** 쓰면 다음 교체 때 또 손으로 찾아야 한다.

### 대비 관문 — 이게 핵심이다

쓰기 전에 31건을 검사하고 **하나라도 미달이면 아무 파일도 쓰지 않는다.**
밝은 색을 accent 에 넣어 확인해 봤다 — 1.62:1 로 막혔다.

만들자마자 실질적인 것을 잡았다. `--danger` 는 흰 카드 위 **4.05**,
`--success` 는 **3.35** 로 둘 다 보라 시절부터 기준 미달이었다.
사람이 매번 기억하는 대신 여기서 막는다.

### 면적용과 글자용을 나눈다 — 세 번 같은 문제를 겪었다

| 면적 | 글자 | 왜 |
|---|---|---|
| `--accent` | `--accent-ink` | 살구에서 2.37:1 |
| `--point` | `--point-ink` | 금색 알약 위 금색 글자 2.01:1 |
| `--danger` `--success` | `--danger-ink` `--success-ink` | 4.05 / 3.35 |

먹청은 어두워서 `--accent` = `--accent-ink` 지만 **토큰은 따로 둔다.**
다음에 밝은 색을 고르면 그때 값만 갈라진다.

`--success-ink` 는 명도만 낮추지 않고 **색상을 130°로 밀었다.**
먹청(190°)과 32° 밖에 안 떨어져 어둡게만 하면 밝기 차까지 줄어(2.08 → 1.44)
강조색인지 개선인지 헷갈린다. 130°면 60° 벌어진다.

⚠️ 앱들이 아직 `-ink` 의미색 두 개를 쓰지 않는다. 글자 자리를 바꾸는 것은
의미색의 외형을 바꾸는 일이라 따로 진행한다.

### 선언 없이 쓰이는 변수를 함께 본다

색을 옮길 때마다 **원래 비어 있던 토큰**이 나왔다. myjane 12개(카드 배경·입력칸
테두리가 통째로 빠진 채 렌더되고 있었다), myjane admin 5개, SnapWord 2개.
`var(--x)` 사용과 선언을 대조하는 것을 절차에 넣을 것.

## 리터럴을 걷어낼 때 어디를 보는지

이제 `palette.json` 한 곳이 원본이지만, 새 화면을 만들다 리터럴이 다시 스며들 수 있다.
2026-09-07 에 245곳을 걷을 때 나온 자리들이다 — 다음에도 같은 데를 본다.

- **하드코딩된 `#fff`** — 먹청 버튼 위 글자라면 `--on-accent`,
  짙은 면 위 글자라면 `--on-dark`. **자리마다 다르므로 일괄 치환하면 안 된다.**
- **순수 검정 `#000`** — 강조색 배경 위 글자로 24곳에 있었다(3.01:1). `--on-accent` 로.
- **그림자** → `rgba(var(--shadow-rgb), α)`
- **장식 SVG stroke** — 인라인 rgba 로 박혀 있다. 헥스만 훑으면 놓친다.
- **`themeColor`** (`app/layout.tsx`) · **`manifest.ts`** 의 `theme_color`·`background_color`
- **모달 backdrop** `rgba(0,0,0,.4)`
- **이메일 템플릿** — CSS 변수를 못 쓴다. 리터럴이 남을 수밖에 없는 유일한 자리다.
  각 앱이 자기 브랜드 색을 쓴다(SnapWord·SnapNote 는 민트였다가 먹청으로 맞췄다).
- **선언 없이 쓰이는 CSS 변수** — 사용과 선언을 대조한다. 매번 나왔다.

### 건드리지 않는 색

- SnapWord `BouncingSmiley.tsx` · 단어 상세의 `NEON` 배열 — 튀는 스마일리용 무지개색
- fitlog `ThemeProvider.tsx` 의 커스텀 테마 기본값 — 사용자가 고르는 값이다
- 금색 `#c9a84c` · `#e8c96a` · `#ead58c` — 결쩜사에서 온 자산

## 아직 안 옮긴 것

- **워드마크의 `jane` 색.** 푸터에서는 `--accent-on-dark` 로 맞췄지만, 다섯 앱의
  `.myjane-mark` 규칙은 여전히 하드코딩이다 → [[앱 공통 UI와 아이콘]]
- **의미색의 글자 자리.** `--danger-ink` · `--success-ink` 토큰은 만들었지만
  앱들이 아직 `--danger` · `--success` 를 글자로 쓴다(4.05 / 3.35).
  의미색의 외형이 바뀌는 일이라 따로 진행한다.
