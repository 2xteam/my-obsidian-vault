# 앱 공통 UI와 아이콘

SnapWord · SnapNote · FitLog · 2hbk · 포털이 **기술적으로** 공유하는 시각 체계.
서비스를 하나의 제품처럼 설명하는 것과는 다른 이야기다 → [[서비스 카테고리와 카피 원칙]]

## 테마 — **네 앱 모두 라이트가 기본** (2026-09-03 정리)

| 앱 | 테마 | 선택 UI |
|---|---|---|
| 포털 | 라이트 전용 | 없음 |
| **SnapWord · SnapNote** | **라이트 전용** | 없음 |
| FitLog | 라이트(기본) · 퍼플 다크 · 커스텀 | 없음 (정의만 있다) |
| 2hbk | 라이트(기본) · 퍼플 다크 · 커스텀 | `/my` |

라이트 값은 네 앱이 **똑같다** — `#fdfbff` / `#7c3aed` / 금 `#c9a84c`.
앱을 오갈 때 밝기가 바뀌면 같은 제품으로 보이지 않는다.

2026-09-03에 두 Snap 앱의 테마 선택을 **없앴다**(사용자 지시). `lib/theme.ts`와
`ThemeProvider`, `data-theme` 속성, 첫 페인트 초기 스크립트를 모두 지웠다.
FitLog의 네온핑크(`violet`)도 함께 없앴다 — 아래 함정.

기본 테마를 바꿀 때 함께 고쳐야 하는 곳 (테마가 여럿인 앱) —

- `app/globals.css`의 `:root` (첫 페인트가 기본 테마와 같아야 한다)
- `lib/theme.ts`의 `DEFAULT_THEME`
- `components/ThemeProvider.tsx`의 초기 상태·컨텍스트 기본값
- `app/manifest.ts`의 `background_color` · `theme_color`

> ⚠️ **라이트를 `:root`에 둘 때 블록 순서.** `<html data-theme="dark">`는 `:root`와
> `[data-theme="dark"]`를 **둘 다** 만족하고 특정도가 같다. 라이트를 `:root`에 두면서
> 다크를 그 앞에 쓰면 나중에 온 라이트가 이겨 다크가 먹지 않는다.
> **라이트 → 다크 순서로 쓴다.** 구조 값(radius·nav 높이)은 테마 블록에서 떼어
> 별도 `:root`에 둔다 — 한 블록에만 있으면 기본 테마가 바뀔 때 사라진다.

### ⚠️ 팔레트를 바꾸면 **액센트 위 글자색**을 함께 봐야 한다

옛 액센트는 밝은 민트(`#1ab485`)·네온핑크였고 그 위에서는 `color: "#000"`이 읽혔다.
결쩜사 라이트의 액센트는 진한 보라(`#7c3aed`)라 검정이 거의 보이지 않는다.
2026-09-03에 두 Snap 앱에서 **버튼 32곳**이 이 상태였다.

`--on-accent`(=`#fff`)를 쓴다. 팔레트가 또 바뀌어도 따라간다.
찾는 법 — `app`·`components`에서 `color: "#000"` 을 그레프해 주변에 `var(--accent)`가
있는지 본다.

> **새 앱을 만들 때도 그대로 따라온다.** 2026-09-04 TypeLog 가 FitLog 의 `app/login/page.tsx`
> 를 복사했더니 액센트 버튼의 `color: "#000"` 과 검정 그림자
> (`0 25px 50px -12px rgba(0,0,0,0.4)`)가 함께 넘어왔다. **파일을 복사하면 이 함정도
> 복사된다** — 복사 직후 `color: "#000"` 과 `rgba(0,0,0` 을 그레프한다.

### ⚠️ 없앤 테마가 브라우저에 남아 있다

`localStorage`에 옛 테마 id가 남아 있으면 그 팔레트로 그려진다. FitLog 랜딩이
"깨져 보인다"는 제보의 원인이 이것이었다 — 네온핑크에서는 시트와 배경이 구분되지
않고 헤더 버튼이 아예 보이지 않았다.

**없앨 때는 저장된 값을 기본값으로 흘려보내야 한다.** `loadTheme()`의 `validIds`와
`layout.tsx`의 초기 스크립트 **두 곳 모두** 고쳐야 한다.

### 어두운 채로 두는 것

사진을 다루는 전체 화면 도구는 **의도적으로 어둡게** 둔다 — SnapNote의 이미지
자르기(`ImageCropper`)와 모노톤 조절(`MonoAdjust`). 어두운 패널 + 흰 글자로
자기 완결이라 테마와 무관하다.

스마일 포인트(카드의 작은 얼굴, 채팅 버튼, 빈 화면의 얼굴)도 자기 색을 쓰는 SVG라
배경이 바뀌어도 산다. 팔레트를 바꿀 때 건드리지 않는다.

**포털(www.myjane.co.kr)은 라이트 전용**이다. 테마 전환이 없고 결쩜사 팔레트
(`#fdfbff` / `#7c3aed` / 골드 `#c9a84c`)를 쓴다. 참고 사이트가 라이트 전용이라
다크를 얹는 순간 대조가 어긋났다 → [[MyJane]]

## CSS 변수

```css
--bg-primary --bg-secondary --bg-card --bg-elevated
--border --border-subtle
--text-primary --text-secondary --text-muted
--accent --accent-hover --accent-subtle
--point --point-subtle
--danger --danger-subtle --success --success-subtle --warning
--input-bg
```

색을 직접 쓰지 않고 **항상 변수로 참조**한다. 그래야 테마 전환이 깨지지 않는다.
예외는 아래 워드마크의 브랜드 보라 하나뿐이다.

## 루트는 소개 페이지, 로그인은 `/login` (2026-09-03)

네 앱 모두 루트(`/`)가 곧 로그인 화면이어서 **그 앱이 무엇을 하는 곳인지 알 방법이
없었다.** 로그인을 `/login`으로 옮기고 루트를 로그인 없이 볼 수 있는 소개 페이지로 바꿨다.

- 소개 페이지는 결쩜사 시트 구조를 따른다 — 히어로(dark) → HOW IT WORKS(tint) →
  WHAT YOU GET → ONE ACCOUNT(gold) → START, 그리고 어두운 푸터
- 로그인 상태로 갈리는 조각은 `components/LandingAuth.tsx`로 떼어 둔다
- 포털에서 들어오는 링크는 **여전히 `/home`** 이다. 소개 페이지를 거치지 않는다
- `(app)` 화면은 `components/AuthGate.tsx`가 지킨다. 예전에는 세션이 없어도
  빈 껍데기를 그리고 API만 401로 조용히 실패했다

SnapWord·SnapNote에는 시트 CSS와 `Sheet.tsx`가 없어 함께 이식했다.
두 앱에는 `--gold`가 없으므로 같은 역할인 `--point`를 쓴다.

## 공통 요소

- **TopNav** — 로고 + 앱 스위처(다른 앱 아이콘) + 메뉴 + 테마 선택
  주기능이 아닌 항목(My · Notice · Q&A)은 PC에서 `More ▾` 드롭다운,
  모바일에서는 구분선 아래로 내린다. 상단 메뉴 표기는 영어(`Home` `Inbody` `History`)
- **FloatingChat** — 우하단 AI 상담 버튼.
  FitLog는 **근육을 불끈 쥐는 팔**이다(회전 없음). 사용자가 준 선화 이미지를
  모티브로 아웃라인으로 그린다 — 주먹 · 엄지 · 아래팔 · 바깥 윤곽 · 이두 · 주름.
  힘을 줬다 폈다 하는 동안 이두만 부풀고, 그 순간 링과 스파크가 한 번 퍼진다.
  **선화는 이두를 크게 키우면 아래팔 선과 어긋난다** — 부푸는 양을 1.05~1.16으로 줄인다.
  세 앱 모두 대화가 비어 있으면 소개와 **질문 예시 칩**을 대화처럼 먼저 보여준다.
  빈 화면은 무엇을 물어봐야 할지 모르게 만든다. 예시는 앱의 대화 정책에 맞춘다
  (SnapWord 영어 학습 · SnapNote 오답 풀이 · FitLog 체성분).
  단, **스레드를 불러오는 동안에는 띄우지 않는다** — 이력이 있는데 안내가 깜빡인다
- **SiteFooter** — 서비스 한 줄 설명 + myjane 워드마크 + `@2026 MyJane All rights reserved`
  (**좌측 정렬**)
- **Toast** — 상단 알림

접힌(모바일) 메뉴의 `Logout`은 위 링크들과 **같은 줄 높이·정렬**로 맞춘다.
`.topnav-logout`(작은 알약 버튼)을 그대로 쓰면 글씨가 작고 안쪽으로 들여써져 튄다.
`.topnav-menu-link .topnav-menu-logout` 조합으로 두고 밑줄만 없앤다.

## myjane 워드마크

푸터에서 포털로 나가는 링크는 `MyJane` 평문이 아니라 워드마크로 쓴다.

```html
<a class="myjane-mark" href="https://www.myjane.co.kr">my<span>jane</span></a>
```

| 부분 | 색 | 이유 |
|---|---|---|
| `my` | `var(--text-primary)` | 배경을 따라간다. 흰 배경에서 검정, 어두운 배경에서 흰색 |
| `jane` | 다크 `#a78bfa` · 라이트 `#7c3aed` · custom `#8b5cf6` | **브랜드 색이라 앱 테마와 무관하게 보라 고정** |

`jane`에 `var(--accent)`를 쓰면 안 된다. SnapWord·SnapNote의 액센트는 민트여서
초록색 `jane`이 나온다. custom 테마는 배경을 미리 알 수 없어 양쪽에서 읽히는
중간 톤(`#8b5cf6`)을 쓴다.

포털 자신의 푸터는 어두운 배경이므로 `my`가 흰색, `jane`이 `#a78bfa`다
(`.site-footer-brand .brand-word > span`).

`my`와 `jane`은 **한 요소 안의 텍스트 노드 + span**이다. flex + `gap`을 주면
둘 사이가 벌어져 `my jane`으로 보인다. `.brand-word`로 감싸 `display:inline-block`으로 둔다.

## 앱 아이콘 — 게이지 호

2026-09-02에 흰 타일 + 빨간 선화에서 **짙은 보라 타일 + 게이지 호**로 전면 교체했다.
세 앱이 같은 기하학을 쓰고 안쪽 심볼만 다르다.

```
타일   192×192, rx 44, linear-gradient(150deg, #3a1266, #1c0733)
호     <circle cx="96" cy="106.46" r="60"> 2개를 rotate(158.96 96 106.46) 안에 둠
       stroke-width 11, round cap
       라일락 트랙  stroke-dasharray="232.6 144.4"  #6b4a9e
       골드 진행    stroke-dasharray="128 249"      #e8d18a
심볼   흰색 선, stroke-width 11, round cap
       SnapWord  가로선 3개 (y=82 / 102 / 122)
       SnapNote  체크  M68 102 L88 122 L128 74
       FitLog    꺾은선 M64 114 L86 90 L106 100 L128 74
       2hbk      별 (5각, 외반경 38 · 내반경 15.6, 중심 96,99) — 선폭 7
                 **대각선으로 절반만 채운다** (좌하단, x−y=−3 기준)
```

2hbk의 별은 **선이 두꺼우면 내부를 다 덮어** 절반 채운 것이 보이지 않는다.
외반경 31·선폭 9로는 반쪽이 구분되지 않았다. 38·7로 키우고 얇게 해야 읽힌다.

채우는 방향(좌하단 → 우상단)은 아래 게이지 호가 도는 방향과 같게 맞춘다.
같은 `<path>`를 `<use>`로 두 번 그린다 — 하나는 `clip-path`로 잘라 채우고,
하나는 윤곽선만.

앱 스위처에는 **자기 앱을 뺀 나머지 셋**을 넣는다(`otherApps`).

**두 호는 같은 `<circle>`을 `stroke-dasharray`만 바꿔 그린다.** 처음에는 골드 호를
`<path>`로 따로 그렸는데 끝점이 라일락 원에서 13.8px(SnapWord) / 6.2px(FitLog)
벗어나 "금색이 붕 떠 보인다"는 지적을 받았다. 같은 원을 쓰면 어긋날 수가 없다.

SVG 원본은 각 저장소 `public/app-icon.svg`에 둔다. PNG는 sharp로 파생한다.

| 파일 | 크기 | 쓰임 |
|---|---|---|
| `icon.png` | 192 | PWA · 일반 |
| `favicon.png` | 32 | 탭 |
| `site-title-icon.png` | 64 | TopNav 로고 |
| `*-link-icon.png` | 56 | 다른 앱 스위처 |
| `<app>-icon-512.png` | 512 | 원본 보관 |

PNG 파생은 프로젝트에 이미 들어와 있는 `sharp`로 한다(Next의 전이 의존성).

```js
sharp(svg, { density: 600 }).resize(size, size).png().toFile(path)
```

### 포털 아이콘 — 소문자 `mj` (2026-09-04 교체)

**예전에는 사용자가 준 사진(`myjane/public/app-icon-source.jpg`)에서 파생했다.**
다섯 앱과 기하학이 달라 스위처 줄에서 혼자 튀었다. 2026-09-04에 같은 타일·게이지 호를
쓰는 **직접 그린 SVG**로 바꿨다. 원본은 `myjane/public/app-icon.svg`,
PNG는 `npm run icons`로 파생한다(`myjane-icon.png` 512 · `icon-192.png` ·
`apple-touch-icon.png` 180 · `favicon-32.png`). 옛 jpg는 지우지 않고 남겨 뒀다.

```
글자      소문자 m + j. 흰색, 획 11 — **다른 앱 심볼과 같은 굵기**
m         아치 두 개, 폭 24. 획 11 에서 속이 막히지 않는 최소 폭이다
j 기둥    x 121.2, y 86 부터
j 꼬리    A 42 42 0 0 1 40 128 — 게이지 호에 **내접**하는 반경 42 원
별        j 위의 점을 4갈래 별로. 게이지 호와 같은 금색 #e8d18a
```

**글자 획을 호와 같게 11로 맞추는 것이 핵심이다.** 9로 두면 붙는 자리에 계단이
생겨 "억지로 붙인 것처럼" 보인다. 이것 하나가 이 아이콘의 성패를 갈랐다.

> ⚠️ **글자를 게이지 호에 잇는 방법 — 접선만 맞추면 부족하다.**
> 세 번 고쳐서 얻은 결론이다.
>
> | 시도 | 결과 |
> |---|---|
> | 자유 곡선 + 끝점 접선만 일치 | 곡률이 달라 이어붙은 자리가 보인다 |
> | 호와 **같은** 원(반경 60)을 탄다 | 이어짐은 완벽하지만 바닥이 y 166.5 까지 내려가 아래로 무거워진다 |
> | 호의 끝에 **내접**하는 작은 원(반경 42) | 내접점에서 방향이 저절로 같고, 바닥은 y 154.9 로 얕다 ✅ |
>
> 그리고 곧은 기둥은 **그 원의 가장 오른쪽 점**에서 시작한다. 그 점의 접선이 정확히
> 수직이라 보조 곡선 없이 곡선으로 넘어간다. 보조 곡선을 두면 오른쪽으로 부풀어
> **팔꿈치처럼 꺾여** 보인다.

> ⚠️ **좌표만 보고 판단하지 말 것.** 실제로 래스터화해 보기 전에는 알 수 없다.
> TypeLog 토끼는 첫 시안이 고양이로 읽혔고, mj 는 굵기 차이가 눈에 보이지 않았다.
> `sharp` 로 192 / 64 / 32 / 16 을 뽑고 **32px 을 보간 없이 8배 확대**해 확인한다.
