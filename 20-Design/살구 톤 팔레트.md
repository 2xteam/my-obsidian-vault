# 살구 톤 팔레트

myjane이 2026-09-06부터 쓰는 색이다. [[결쩜사 디자인 시스템]]에서 **시트 쌓기,
아이브로우 → 헤드라인 → 본문, 금색 포인트는 가져오고 색과 명도 구조를 갈았다.**
페이지 구성은 여전히 [[결쩜사 페이지 패턴]]을 따른다.

단 **"짙은 시트 + 어두운 푸터로 닫기"는 가져오지 않는다.** 색만 바꾸고 그 골격을
남겼다가 실패했다 → 아래 [[#⚠️ 밝은 팔레트에 어두운 면을 남기면 안 된다]]

## 왜 바꿨나

결쩜사 패턴을 그대로 쓰다 보니 색까지 같아서 너무 닮았다.
사용자가 네이버 예약 프로모션 배너(크림 바탕 + 살구 코랄 + 연분홍 일러스트)를
보여주며 "이런 스타일"을 요청했다.

**중요한 발견 하나 — 그 이미지에서 따뜻함을 만드는 건 코랄이 아니라 바탕이다.**
크림 `#FDF6F0` 이 인상의 8할이다. 그래서 강조색을 감청이나 먹청으로 바꿔도
결쩜사와 완전히 다른 인상이 나온다. 색을 고를 때 이걸 먼저 알아야 한다.

## 색 토큰

```css
/* ★ 표시는 레퍼런스 이미지에서 실측한 값 (히스토그램 최빈색) */
--bg:            #fff5ef;                    /* ★ 크림 바탕 */
--surface:       #ffffff;                    /* ★ 카드 — 순수 흰색. 아래 예외 절 참고 */
--surface-hover: #fdeae2;                    /* 연분홍 시트(tint) */
--border:        rgba(166, 75, 47, 0.14);
--border-strong: rgba(166, 75, 47, 0.4);
--text:          #2c1f1a;                    /* 따뜻한 먹 */
--text-dim:      #7a5f52;

--accent:      #ff805d;                      /* ★ 넓은 면적 채우기 전용 */
--accent-ink:  #a64b2f;                      /* 글자·아이콘·테두리 */
--on-accent:   #2c1f1a;                      /* 살구 배경 위 글자색 */
--accent-soft: rgba(255, 128, 93, 0.12);
살구 버튼:     linear-gradient(135deg, #ff8a68, #f9744f)

--gold-from: #d2643f;                        /* 헤드라인 그라디언트 */
--gold-to:   #a64b2f;
--gold:      #c9a84c;                        /* 좁은 면적만 */

/* 밝은 면 — 랜딩은 이것만 쓴다 */
히어로 시트:    linear-gradient(168deg, #fffaf6, #fbeae0 74%, #f7dbd0)
푸터 띠:        var(--surface-hover) + 위쪽 실선 1px
시트 그림자:    0 20px 48px rgba(74, 40, 26, 0.06)

/* 어두운 면 — 로그인·회원가입의 이야기 패널(.auth-story)에서만 쓴다.
   랜딩에는 쓰지 않는다 → 아래 "밝은 팔레트에 어두운 면을 남기면 안 된다" */
짙은 패널 배경: linear-gradient(150deg, #241310, #3b2016 65%, #4b2a1c)
어두운 곳 글자:  #fdf6f0 / rgba(250, 235, 226, 0.74)
어두운 곳 살구:  #f0a184
어두운 곳 금색:  #ead58c
```

## ⚠️ 가장 중요한 규칙 — 강조색은 두 단계다

**밝은 살구로 글자를 쓰면 안 된다.** 이걸 어기는 게 이 팔레트의 유일한 함정이다.

| 색 | 크림 위 | 흰 글자 |
|---|---|---|
| 살구 `#FF805D` | **2.30** | **2.47** |
| 진한 살구 `#A64B2F` | 5.33 | 5.72 |
| (참고) 이전 보라 `#7C3AED` | 5.32 | 5.70 |
| 금 `#C9A84C` | 2.13 | 2.29 |

**레퍼런스 자신의 코랄도 흰 글자로 2.47:1 이다.** 저쪽 페이지는 코랄 알약에
흰 글자, 코랄 카드에 노란 글자(2.11:1)를 쓴다 — 즉 기준 미달인데 "STEP 01"처럼
읽지 않아도 되는 장식 라벨이라 넘어가는 것이다.
**색값은 실측해서 가져오고 글자색 규칙은 가져오지 않는다.** 이게 요령이다.

통과하는 조합 (실측값 채택 후):

| | 크림 `#FFF5EF` | 흰 카드 `#FFFFFF` | 살구 `#FF805D` |
|---|---|---|---|
| 먹 `#2C1F1A` | 14.84 | 15.93 | 6.45 |
| 잉크 `#A64B2F` | 5.33 | 5.72 | — |
| 흐린 글자 `#7A5F52` | 5.45 | 5.86 | — |

살구는 큰 글자 기준(3:1)에도 미달한다. 그래서

- 글자·아이콘·**테두리**는 `--accent-ink` — 색상(hue 14°)은 그대로 두고 명도만 낮춘 값
- 살구 버튼 위 글자는 흰색 대신 **짙은 먹** `#2C1F1A` (6.28:1)
- 금색도 글자로 쓰면 안 된다. 배지 배경·구분선 같은 좁은 면적에만.

### 순수 흰색은 예외다

"순수한 검정·회색·흰색을 쓰지 않는다"는 [[결쩜사 디자인 시스템]]에서 온 규칙이고,
그쪽 중립색에 보라가 섞여 있기 때문이었다. 따뜻한 크림 위에서는 사정이 다르다 —
**흰 카드가 떠오르는 것이 이 스타일의 밝음을 만드는 축이다.**
레퍼런스의 카드도 정확히 `#FFFFFF` 다. `--surface` 한 곳만 예외로 둔다.
검정·회색은 여전히 안 쓴다.

참조한 배너는 살구 바에 흰 글자를 얹었다. **그건 한 번 보고 지나가는 광고라 되는 것이고,
매일 수치를 읽는 앱 화면에서는 안 된다.** 참조 이미지를 그대로 베끼면 여기서 걸린다.

토큰 이름이 `--accent` / `--accent-ink` / `--on-accent` 로 나뉘어 있어도 값이 다 같으면
분리가 놀고 있는 것이다. myjane이 정확히 그 상태였다 — 셋 다 보라 하나.

## 의미색과 부딪히지 않는지

fitlog는 위험 `#e0455f`(장미), 개선 `#2f9e74`(청록 초록)을 쓴다 →
피검사 "벗어난 항목" 알약, 인바디 증감 표시.

- **초록·와인 계열 강조색은 이 시점에서 탈락**이다. 강조인지 경고인지 구분이 안 된다.
- 살구는 위험색과 색상환에서 26° 밖에 안 떨어져 있지만, 글자를 `--accent-ink`
  (어두운 벽돌)로 쓰는 순간 **밝기가 1.41배 벌어져** 갈린다.
  → 강조색 분리가 접근성 문제만 푸는 게 아니라 의미 충돌까지 푼다.

오류 문구용으로 `--danger: #b02742` 를 골랐다(크림 위 6.10:1).
**살구 강조색과 나란히 놓이는 자리에는 쓰지 말 것** — 각도가 가깝다.

## 검증 방법

눈으로 보지 말고 렌더된 페이지에서 재라. 조상을 타고 올라가 **실제로 칠해진 배경**을
찾아 대비를 계산하는 스크립트를 브라우저에서 돌렸다(글자 61개 → 미달 0건).

이 방법으로 두 개를 잡았다. 둘 다 **팔레트 규칙을 문서에 쓰고 나서도 코드에서 어긴** 자리다.

- 워드마크의 `jane` — `var(--accent)` 라 2.48:1
- 입력칸 포커스 테두리 — `var(--accent)` 라 크림 위 2.37:1, 포커스가 안 보인다

주의: 배경이 `linear-gradient` 인 요소는 `backgroundColor` 가 투명으로 나온다.
그냥 조상을 타면 크림까지 올라가 **어두운 시트 위 글자를 거짓 미달로 잡는다.**
그라디언트를 만나면 대표색을 넣어주는 예외가 필요하다.

## 다른 앱에 옮길 때

토큰 이름이 5개 앱에 동일해서 값 치환에 가깝다. 다만 아래를 함께 봐야 한다.

- **하드코딩된 `#fff`** — 살구 버튼 위 글자라면 `--on-accent`,
  어두운 배경 위 글자라면 `#fdf6f0`. 자리마다 다르므로 일괄 치환하면 안 된다.
- **보라 계열 그림자** `rgba(37,13,62,α)` → `rgba(74,40,26,α)`
- **장식 SVG stroke** — 인라인 rgba로 박혀 있다
- **`themeColor`** (`app/layout.tsx`)
- **선언 없이 쓰이는 CSS 변수** — 다른 앱 마크업을 가져올 때 토큰 이름만 따라오는
  일이 흔하다. myjane에 12개가 있었고 그 화면들은 카드 배경·입력칸 테두리가
  통째로 빠진 채 렌더되고 있었다. 옮기기 전에 사용/선언을 대조해 볼 것.
- **이메일 템플릿은 건드리지 말 것** — myjane 저장소에 있는 것은 SnapWord
  브랜드 메일(민트 `#2ee8ae`)이다. 통합 인증이 myjane에 있어 파일만 여기 있다.

## ⚠️ 밝은 팔레트에 어두운 면을 남기면 안 된다

색만 갈고 결쩜사의 **짙은 히어로 + 어두운 푸터로 닫기** 골격을 그대로 뒀더니,
크림 바탕인데도 무거웠다. 사용자가 바로 알아챘다 —
"뭔가 더 밝은 분위기가 있습니다, 어두운 보라색을 썼던 패턴의 잔재인 것 같다".

**밝은 팔레트에서 어두운 면은 그 자체로 시선을 끌어당겨 분위기를 결정해 버린다.**
크림이 8할이라고 해도, 검은 띠 하나가 그 8할을 되돌려 놓는다.
참조한 프로모션 배너를 다시 보면 짙은 면이 **한 곳도 없다** — 크림에서 시작해
코랄 버튼으로 끝난다. 색만 베끼고 명도 구조를 안 베낀 것이 실수였다.

그래서 랜딩(myjane 메인)에서는 어두운 면을 아예 뺐다.

| 원래 | 바꾼 것 |
|---|---|
| `.sheet--dark` 짙은 먹갈 히어로 | `.sheet--hero` 크림→연분홍 `#fffaf6 → #f7dbd0` |
| `.site-footer` `#20120d` 검은 띠 | 연분홍 `--surface-hover` + 실선 하나 |
| `.hero-badge` 반투명 흰색+크림 글자 | 흰 알약 + 잉크 글자 |
| `.btn-ghost` 반투명 흰색+크림 글자 | 흰 알약 + 잉크 글자 |
| 시트 그림자 `0.09` | `0.06` — 짙으면 시트가 무겁게 내려앉는다 |

어둠으로 만들던 히어로의 존재감은 **(1) 그라디언트 (2) 한 단계 큰 헤드라인
(3) 살구 버튼** 세 가지로 대신한다.

**로그인·회원가입의 짙은 이야기 패널(`.auth-story`)은 그대로 둔다.**
그쪽은 화면을 반으로 나눠 대조를 만드는 구조라 어두운 면이 제 몫을 한다.
어두운 면을 다 없애는 게 아니라, **한 화면을 어둠이 지배하지 않게** 하는 것이 요점이다.

검사 팁: 히어로가 gradient 라 `backgroundColor` 가 투명으로 나온다.
대비를 잴 때 **가장 어두운 끝**(`#f7dbd0`)을 대표색으로 잡아 최악의 경우로 계산한다.

## 아이콘 — 밝은 페이지라도 아이콘은 짙어야 한다

여섯 개(myjane + 다섯 앱)가 같은 기하학을 공유한다 → [[앱 공통 UI와 아이콘]]
하나만 바꾸면 가족이 어긋나므로 항상 함께 바꾼다.

```
타일     #3a1266 → #1c0733     ⇒  #4b2a1c → #241310
흐린 호  #6b4a9e                ⇒  #c2704c
흐린 호  rgba(200,184,255,.32)  ⇒  rgba(247,200,178,.32)
심볼     #ffffff · #fff         ⇒  #fff5ef
금색     #ead58c · #e8d18a      ⇒  그대로
```

**타일을 밝게 하지 않은 이유.** 아이콘은 32px 파비콘까지 내려가고 획이 11이다.

| 후보 | 결과 |
|---|---|
| 살구 타일 | 금색 호가 **1.69:1** — 사라진다 |
| 크림 타일 | 랜딩 카드가 흰색이라 **1.07:1** — 테두리가 사라진다 |
| 짙은 타일 | 크림 심볼 16.6 · 금색 12.2 · 연살구 호 4.9 — 전부 살아난다 |

페이지에서 어두운 면을 뺀 것과 아이콘이 짙은 것은 **서로 다른 문제다.**
전자는 한 화면을 어둠이 지배하는 문제고, 후자는 작은 물체의 판독성 문제다.

### ⚠️ 함정 — 색이 rgba 로 박혀 있다

SnapWord·SnapNote·fitlog 는 흐린 게이지 호를 `rgba(200,184,255,.32)` 로 썼다.
헥스만 훑는 스크립트가 이 셋을 놓쳐 **아이콘 세 개만 연보라로 남았다.**
여섯 개를 나란히 렌더해 보고서야 눈에 띘다.
색 교체는 **hex · rgba · 축약형(`#fff`)** 을 모두 훑어야 하고,
끝나면 반드시 여섯 개를 한 장에 모아 눈으로 확인한다.

### PNG 파생물

각 앱이 **서로의 링크 아이콘을 갖고 있다.** 하나를 바꾸면 여섯 곳에서 다시 만들어야
하고, 총 56개다. 파일 이름과 **현재 픽셀 크기를 그대로 유지**하며 다시 만든다
(앱마다 favicon 이 32인 곳과 192인 곳이 섞여 있다).
typelog 의 16px 은 단순화한 `app-icon-16.svg` 를 쓴다.

## 원형 장식은 걷어냈다

`.sheet-ornament`(타원 두 개 + 금색 점)와 `.auth-story` 의 호 세 개를 없앴다.
실(結) 모티프였지만 밝은 바탕에서는 얇은 선이 얼룩처럼 보였다.
`radial-gradient(circle at …)` 는 남긴다 — 이름에 circle 이 붙어 있어도
테두리 없는 확산 글로우이고, 히어로의 크림→연분홍 그라디언트를 만드는 것이 이쪽이다.

## 대비 검사 자동화

7개 페이지를 헤드리스 크롬에 **CDP 로 붙여** 실제 렌더 상태에서 잰다.
Node 22+ 의 전역 `WebSocket` 을 쓰면 의존성이 필요 없다.

이 검사가 **팔레트 규칙을 문서에 쓰고 나서도 코드에서 어긴 자리**를 네 번 찾았다.

| 자리 | 쓰던 색 | 대비 |
|---|---|---|
| 워드마크 `jane` | `--accent` | 2.48 |
| 입력칸 포커스 테두리 | `--accent` | 2.37 |
| 복구 페이지 "로그인으로" 링크 | `--accent` | 2.47 |
| placeholder | 브라우저 기본 `#757575` | 4.29 |

`--placeholder: #85695b` 토큰을 두고 전역 `::placeholder` 로 깔았다
(크림 4.69 · 흰 카드 5.04). 파이어폭스는 기본 opacity 를 깎으므로 `opacity: 1` 이 필요하다.

**Git Bash 함정:** `/login` 같은 인자를 윈도우 경로로 바꿔버린다
(`C:/Program Files/Git/login`). 그러면 아무것도 재지 않고 "미달 0건"이 나온다 —
거짓 통과다. `MSYS_NO_PATHCONV=1` 을 붙이고, **검사한 글자 수를 꼭 함께 출력**해
0개가 아닌지 본다.
